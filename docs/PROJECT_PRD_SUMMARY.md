## 1. 项目定位

Oracle Recovery Service 是一个面向内部数据恢复、数据接入、Doris 脱敏加密、批量授权和数据平台编排的工具系统。

当前系统覆盖以下能力：

- 用户登录、管理员、用户管理和权限控制。
- 数据连接管理。
- Oracle / SQL Server / MySQL 恢复目标管理。
- Oracle DMP 自动探测与导入。
- Doris CSV 导入。
- Doris SM3 映射反查。
- Doris SM4 加密中心。
- JSON / CSV 文件脱敏解密。
- 批量授权中心。
- 离线开发、调度任务和执行日志。
- 数据变化触发器和 Doris 数据同步组件。
- 接口编排中心与 SQL 包装为 API。
- 数据库清理与审计。

## 2.3 业务微服务拆分第一阶段

当前项目允许从同一代码基座构建多个业务镜像或用同一镜像以不同环境变量启动不同服务。第一阶段拆分原则：

- 共享系统元数据库 MySQL、Redis、用户权限、审计和数据连接配置，不在本阶段拆分数据库 schema。
- 保持现有前端入口和 `/api/v1` 路径兼容；需要独立暴露时，由网关或部署脚本把业务服务挂到原路径。
- API 服务支持按 `APP_SERVICE_MODE` 选择路由集合；默认 `monolith` 保持全量兼容。
- Worker 服务支持按 `WORKER_SERVICE_MODE` 和 `WORKER_QUEUES` 选择业务队列；默认兼容旧单 Worker。
- 数据同步手工运行必须先落库独立运行记录，再投递到 `data_sync` 队列执行；API 只负责提交和回读日志，避免 100 表级长任务占用 API 进程。
- 业务长任务必须投递到明确队列，避免 Oracle 大任务、SM4 批次、SM3 任务、SQL ETL 或数据同步互相抢占。

第一阶段服务模式：

| 服务模式 | 主要职责 | 默认队列 |
|---|---|---|
| `gateway` / `monolith` | 登录、用户、API Key、静态 UI、公共入口、连接、审计、全部兼容路由 | 无 |
| `oracle-restore` | Oracle/SQL Server/MySQL 恢复任务、Oracle DMP 导入、停止、重试 | `oracle_restore` |
| `data-sync` | 数据同步任务、表映射、独立运行日志、数据同步执行 | `data_sync` |
| `data-platform` | 离线开发、版本、调度、数据变化触发器编排 | `data_platform` |
| `sm4` | Doris SM4 加密任务、密钥函数、文件解密、SM4 批次 | `doris_sm4` |
| `sm3` | Doris SM3 映射任务与反查 | `doris_sm3` |
| `doris-sql` | Doris SQL / SQL ETL 任务 | `doris_sql` |
| `api-orchestration` | HTTP/SQL API 连接器、流程定义、发布、运行和逐节点日志 | `api_orchestration` |

验收要求：

- 默认 `monolith` 启动方式的旧行为不变。
- 独立 Worker 启动时只消费所属队列，任务投递队列可从配置覆盖。
- 独立 API 服务模式只加载该业务所需路由和公共健康/鉴权依赖，不误暴露无关高风险入口。
- Docker Run 启动脚本仍兼容老 Docker 17.03；新增容器必须保留 `--security-opt seccomp=unconfined`、`--pids-limit -1`、`--ulimit nproc=65535:65535`。
- 未明确“打包”前，只在本地源码和测试环境验证，不生成完整部署包。
- 当 128 上已经存在最新热更新且完成真实验证的版本时，后续“打包”必须以 128 当前运行的热更新状态为唯一基线，再同步回本地生成完整包；不得回退到本地旧源码、旧镜像或旧包重新组装覆盖已验证能力。

## 2.1 基础表单交互硬规则

以下规则适用于全系统所有新增和改造表单，属于基础需求，不允许由具体模块自行弱化：

- 存在上下游依赖的数据项必须使用联动选择控件，不得要求用户重复手工输入系统已经能够读取的连接、Catalog、数据库、表、字段、任务或版本。

- 字段、参数和操作控件必须按当前业务条件动态展示。当前条件不需要的字段必须隐藏、清空且不提交，不能仅通过视觉隐藏保留旧值。

- 元数据读取必须提供加载中、无数据和失败状态；快速切换上游条件时，旧请求结果不得覆盖新选择。
- 动态表单在最大化、左右半屏和普通窗口下均应保持可读、可操作，不得因条件字段显示或隐藏造成控件重叠、页面横向溢出或主要操作不可见。

## 5. Oracle DMP 自动导入

### 5.1 目标

用户通常拿到外部单位提供的 Oracle `.dmp` 文件，但不知道它是 Data Pump、老 exp、整库、schema、表级还是分卷导出。系统需要自动探测、生成计划，并在用户确认后导入到专用 Oracle 还原仓库。

### 5.2 核心规则

- 默认 dry-run，只探测和生成计划，不正式导入业务数据。
- 只有显式执行时才使用 `--execute`。
- 支持 Data Pump。
- 支持老 exp。
- 支持分卷 DMP，例如 `xxx_%U.dmp`。
- 支持用户手动指定 DMP 目录和 `DUMPFILE` 模式。
- 支持自动识别 schema、表空间并生成映射。
- 正式导入时自动创建目标用户、目标 Bigfile Tablespace 和 quota。
- 自动导入必须在 PDB 中执行，禁止在 `CDB$ROOT` 中创建还原对象。
- 每次运行生成独立运行目录，包含 `run.log`、`plan.json`、`report.json` 和 Oracle 原生日志。

### 5.3 安全边界

Oracle 自动导入面向专用还原仓库，不面向生产库。

冲突重建时必须保护：

- 系统用户不可删除。
- 系统表空间不可删除。
- DIRECTORY 只有指向工具管理目录时才允许清理。
- 公共 DMP 目录不可被自动清理。

### 5.3.1 直接使用 Oracle DMP 目录的零复制规则

当用户选择“直接使用 Oracle DMP 目录”，且宿主机目录已通过 Docker volume 映射到 Oracle 容器时，系统必须直接读取原始 DMP，不得再次执行 `docker cp`、移动或删除原始文件。

目录职责严格拆分为：

- 共享 DMP DIRECTORY：固定指向容器内已挂载的 DMP 根目录，例如 `RECOVERY_DMP_DIR -> /opt/oracle/recovery_dmp`，只负责读取 DMP。
- 任务工作 DIRECTORY：每次运行创建唯一子目录，例如 `/opt/oracle/recovery_dmp/auto_import/<run_id>`，只存放 SQLFILE、探测日志和 `impdp` 原生日志。
- 系统运行日志目录：任务结束后归档任务工作目录中的日志，供页面展示和下载。

执行规则：

1. 先校验宿主机目录、容器挂载路径和 DMP 文件在容器内真实可见。
2. 共享 DIRECTORY 不存在时允许创建；已存在且路径一致时直接复用并补齐授权。
3. 已存在但路径不一致时必须阻断，不得使用 `CREATE OR REPLACE DIRECTORY` 覆盖其他业务的定义。
4. `impdp` 使用任务工作 DIRECTORY 承载日志，并通过 `DUMPFILE=<共享DIRECTORY>:<文件模式>` 直接读取 DMP，例如 `DUMPFILE=RECOVERY_DMP_DIR:codex_directdmp_%U.dmp`。
5. 任务结束后只清理本次任务工作 DIRECTORY 和工作文件；共享 DIRECTORY 与原始 DMP 永久保留。
6. 任务元数据必须记录 `source_files`、`zero_copy_dump=true` 和 `copied_files=[]`，使零复制事实可审计。

该模式仅适用于已经挂载到 Oracle 容器并通过可见性校验的目录。普通上传、远端文件服务器或容器不可见目录仍需进入受控 staging 流程，不能把“零复制”扩展为未验证路径的直接访问。

### 5.4 宿主机 Python 要求

自动导入脚本运行在 Oracle Docker 宿主机上，不是在 API 容器中执行。因此 Oracle Docker 宿主机必须具备：

```sh
python3 --version
```

并且版本不低于 Python 3.7。

系统执行自动导入前必须：

- 查找远端 `python3`。
- 验证版本 `>= 3.7`。
- 上传脚本后执行 `python3 -m py_compile`。
- 预检查失败时，不继续导入。

2026-07-13 已补齐结构化 preflight：SSH、Python 3.7+、脚本编译、Oracle 容器、`sqlplus/impdp`、DMP 文件模式、容器内 DMP 目录、PDB、DIRECTORY 路径策略均会在正式导入前检查，并返回可读修复建议。

### 5.6 超长任务防重复执行

- Oracle 恢复任务由 Worker 通过数据库条件更新原子认领，只有 `created -> policy_running` 成功的消息可以执行。
- Celery/Redis 重复投递同一任务时必须直接确认并记录“重复消息已忽略”，不得再次连接远端服务器。
- Redis visibility timeout 必须至少大于 Oracle 总操作超时一小时，避免正常超长任务被重新投递。
- Oracle 大数据导入默认按 7 天超时配置，即 `ORACLE_IMPORT_OPERATION_TIMEOUT_SECONDS=604800`；Celery、SSH/docker exec、DMP 探测、SQLFILE 探测和正式 `impdp` 必须共用该配置，不得在局部代码中回退到 48 小时。
- Oracle 大数据导入前必须确认 TEMP tablespace 已扩容；21c 初始化脚本默认追加 recovery tempfile，参数通过环境变量控制，避免索引、排序和约束阶段因 TEMP 不足失败。
- 重试接口只允许已结束任务调用；运行中、排队中任务返回 `409`，不得重新入队。
- 远端自动导入脚本按稳定 `run_id` 持有 POSIX 文件锁；相同运行目录存在活动进程时，后续进程必须在任何清理、复制和 SQL 操作前退出。
- 重复执行不得并发写入同一 `run.log`、`timeline.jsonl`、`report.json`，也不得删除活动任务的 Oracle DIRECTORY。

### 5.7 Oracle 19c 导入停止

- 运行中的 Oracle 19c 自动导入任务支持人工停止，Oracle 21c 不在本能力范围内。
- 每次 `impdp` 使用唯一且可追溯的 `JOB_NAME`。
- 普通停止执行 `STOP_JOB=IMMEDIATE`，保留 Data Pump Job 的后续恢复能力。
- 强制终止必须由用户二次确认，执行 `KILL_JOB` 并仅终止当前任务进程。
- 停止采用 `stopping -> cancelled` 状态闭环；已导入数据不回滚，停止过程和结果必须可审计。

### 5.8 Oracle 分区能力与 Edition 约束

- Oracle 分区表和分区索引的创建、导入与恢复仅允许在 Enterprise Edition（EE）环境启用。
- 项目所称 CE/非 EE 环境不能创建分区表，不得生成或执行 `CREATE TABLE ... PARTITION BY ...`、分区索引等 DDL。
- Oracle 导入预检必须识别目标数据库 Edition 及 DMP 中的分区对象：目标为 EE 时按已认证能力继续；目标为 CE/非 EE 时在正式执行前阻断，并明确提示“当前 Edition 不支持分区表”。
- Edition 不兼容属于确定性能力阻断，不得触发自动重试，也不得在后台持续等待。
- 不得静默丢弃分区定义后将任务标记为完整恢复。未来如支持转换为普通表，必须作为用户显式选择的有损兼容模式，并记录转换范围和审计结果。

### 6.1 模块定位

模块页签：

- 对象选择。
- 任务调度。
- 定时计划。
- 密钥函数。
- 文件脱敏/解密。
- 执行日志。

### 6.2 加密任务

支持：

- 选择 Doris 数据连接。
- 扫描源库、表、字段。
- 按敏感字段关键词自动匹配。
- 手动勾选字段。
- 单表加密。
- 多表批量加密。
- 队列化执行。
- Worker 并发控制。
- 任务停止、取消、复制、重试。
- 从历史任务生成定时计划。
- 全过程日志查询。

### 6.3 字段长度规则

SM4 加密后密文长度会明显增长。为避免目标表插入失败，当前策略要求被加密字段落地时使用足够长度的 `VARCHAR`。

已确认规则：

- Doris 中 `STRING` 不适合作为第一列或主键场景。
- 加密结果字段应优先使用 `VARCHAR(2000)`。
- 对主键、第一列、唯一键等特殊场景，应避免改成 Doris 不支持的类型组合。

### 6.4 密钥函数

对外固定函数名：

```text
CQ_SM4_ENCRYPT
```

实现策略：

- 对外函数名固定。
- 内部 Java UDF 函数按密钥指纹版本化。
- jar 内 Java class/symbol 按版本生成。
- 固定函数名通过 alias 指向当前版本函数。
- 创建后必须使用固定函数名执行 SQL 验证。
- 默认不重启 Doris FE/BE。
- jar 必须编译为 Java 8 兼容 class file version 52.0。
- 编译优先使用 `javac --release 8`，不支持时退回 `-source 8 -target 8`。
- API 与 Worker 必须共享持久卷 `oracle_recovery_sm4_jars:/app/data/sm4-jars`，容器重建不得丢失历史密钥 JAR。
- 系统库保留活跃密钥版本但对应 JAR 缺失时，JAR 下载接口必须按加密保存的密钥种子自动重建同 fingerprint、同文件名的 Java 8 JAR。
- 新建 SM4 批次时应主动确认绑定密钥 JAR 可用；无法恢复时在提交阶段失败，不能等到大量表执行后逐表报 404。
- 批次执行任何目标表删除、创建或写入前，必须验证当前库 `CQ_SM4_ENCRYPT` 的返回值与批次绑定密钥一致；不一致时提前终止并提示刷新该库函数。
- 2026-08-20 起，密钥刷新、批次创建和批次执行按“连接 + 数据库”使用跨实例运行屏障：批次从最终密钥预检到全部表完成期间禁止切换固定函数；存在 queued/reserved/running/stopping 批次时禁止刷新该库密钥；多调度器对 queued 任务执行原子抢占。该保护不修改历史任务、密钥、离线开发快照或调度定义。
- 密钥函数页面按当前 Doris 连接展示业务库树，首次加载默认全部勾选，并支持全选、取消和逐库选择。
- 密钥函数支持复用当前或历史密钥版本，并以逐库加密/解密能力矩阵调整同一密钥的覆盖范围；取消能力会删除对应函数但不改任务、密钥、批次、调度或离线快照。UDF JAR 下载通过 `DORIS_SM4_UDF_JAR_ALLOWED_IPS` 限制单 IP、CIDR 或 IP 范围来源。
- 每个业务库持久展示最近一次函数创建成功或失败状态、密钥指纹和执行时间，页面刷新后仍可追溯。
- SM4 批次按“连接 + 数据库”的最近成功部署记录绑定密钥；目标库没有成功记录或最近创建失败时阻止提交，避免误用其他库的新密钥。
- 尚未产生按库部署记录的历史连接保留连接级密钥回退，兼容已有任务。

### 6.5 自动密钥与解密

已确认业务原则：

- 如果加密任务使用自动生成随机密钥种子，解密时不应要求用户再手动输入密钥。
- 加密任务应记录密钥版本或密钥指纹。
- 文件解密、表解密或后续反查时，应优先通过任务记录自动找到对应密钥版本。
- 手动输入密钥只作为兜底能力。
- 密钥明文不在前端展示。
- 密钥使用过程必须可审计。

2026-07-13 已补齐自动密钥解密闭环：SM4 批次会绑定密钥版本和密钥指纹，文件解密可通过历史加密批次 ID 自动找回密钥版本。

2026-07-15 明确密钥与任务解耦：保存任务、执行一次、离线开发、上线调度和单表加密均不得隐式刷新 SM4 密钥；密钥创建与轮换只在密钥函数模块独立完成，批次提交时绑定目标数据库当前已成功部署并验证的密钥版本。

### 6.6 SM4 任务修订与离线生产快照

- SM4 任务名称是任务定义业务名称，不是别名或离线开发版本名称。
- 新建任务生成新 `task_definition_id` 和 `V1`；编辑保存保持原 ID，内容变化时递增修订号。
- 编辑页直接展示任务名称，并提供“保存任务”和“另存为新任务”。
- 编辑页不提供“提交选中表批次”；一次执行从任务列表“执行一次”发起。
- 保存前展示该任务关联的开发节点、生产节点、在线节点和在线流程范围。
- 离线开发提交生产版本时冻结 SM4 完整配置和修订号。
- 已提交、已上线、已下线生产版本均按各自快照执行，后续修改 SM4 任务不会改变旧生产版本。
- 原开发版或新开发版重新提交上线时，冻结提交当时的最新 SM4 修订。
- 历史生产版本必须可真实回滚，不允许通过任务 ID 动态读取最新配置。
- 生产快照冻结任务连接、库表和修订，但批次密钥按执行时该连接的活跃密钥解析；因此旧生产版本仍可能因旧连接或旧库函数产生不同密钥链路，页面必须明确展示冻结连接与修订。
- 离线开发触发 SM4 批次后，节点结果必须永久保留 `batch_id`；节点失败或服务重启只能追加错误字段，不得覆盖批次关联。
- 对已经被旧代码覆盖的历史失败节点，可从 `SM4 batch <UUID>` 错误文本恢复批次归属，避免调度批次被误显示为“手动提交”。

### 8.2 已确认业务边界

部门库 `DWH_部门名` 是部门用户长期自建表和加工使用的工作区。

部门库不是源表发布目标。

批量授权 Excel 中的库名和表名是源库源表。

实际授权示例：


到期或手动下线时，只回收本批次授予的源表查询权限。

不执行：

- 不把源表发布到部门库。
- 不创建源表视图到部门库。
- 不删除部门。
- 不删除部门用户。
- 不删除部门库。
- 不回收部门库长期基础权限。

### 8.6 权限基线待增强

当前最需要增强的是“权限基线”。

原因：

- 一个用户可能在系统外已经拥有某张源表权限。
- 一个源表权限可能被多个有效授权批次同时授予。
- 到期回收时不能误撤用户原本就有或其他批次仍在使用的权限。

建议新增：

- 授权前快照：执行 GRANT 前记录用户是否已经拥有该源表权限。
- 本批次新增标记：只回收本批次真正新增的权限。
- 批次引用计数：同一用户、同一源表、同一权限被多个批次覆盖时，只有最后一个有效批次下线后才允许 REVOKE。
- 回收前二次校验：如果发现还有其他有效批次或外部权限来源，跳过 REVOKE 并记录原因。
- 审计字段：记录跳过回收、实际回收、回收失败的具体 SQL 和原因。

## 9. 离线开发与任务目录

### 9.0 组件任务资产化

- `Doris SQL`、`数据同步`、`数据变化触发器`均提供独立功能入口，不在离线开发画布内填写详细业务参数。
- 三类能力均支持新建、命名、编辑、保存修订和删除任务；Doris SQL、数据同步支持独立执行一次。
- Doris SQL 工作台及离线节点不对 `INSERT`、`UPDATE`、`DELETE`、DDL、`GRANT`、`REVOKE` 等语句进行中台确认或类型拦截。
- SQL 是否有权执行完全以所选 Doris 连接账号的数据库权限为准；中台仅记录 SQL 类型、执行结果、耗时及 Doris 返回的错误。
- 离线开发节点只选择已保存任务，并展示绑定任务名称、当前修订和最新修订。
- 从离线节点选择“新建任务”时跳转对应独立入口，保存后自动返回并绑定当前节点。
- 开发版保存、提交生产版和上线运行时冻结任务配置及修订快照；独立任务后续修改不改变已提交版本。
- 用户必须显式点击“更新到最新修订”，开发节点才切换到任务的新版本。
- 数据变化触发器是独立的事件驱动子流程，拥有自己的监控配置、内部执行画布、版本、发布状态和运行日志。
- 触发器内部画布可引用已保存的 SM3、SM4、Doris SQL、数据同步/ETL 任务；触发器不能引用触发器，避免递归和循环派发。
- 触发器内部画布使用显式 DAG 连线，不根据节点数组顺序自动生成执行关系；固定监控节点是唯一首节点且不可删除。
- 触发器左侧任务列表与离线开发目录树保持相同紧凑风格；任务行不显示操作按钮，右键提供打开、重命名、复制和删除。
- 节点支持单击选中后按 `Delete` 删除，右键提供复制、编辑、重命名和删除；连线支持选中后按 `Delete` 或右键删除。
- 节点底部输出端口支持拖拽建立有向连线；禁止自环、重复边、回指监控节点和环路。
- 所有执行节点必须从监控节点可达，游离节点在画布中醒目标记并禁止保存；保存、校验和发布由后端统一复核。
- 右侧属性栏只负责选择引用任务和业务属性，不再提供前移、后移和删除等重复操作。
- 离线开发引用整个已发布触发器子流程，不再在离线画布外部重复配置该触发器的下游节点；发布时递归冻结触发器版本及其内部任务快照。
- 独立启用触发器或上线包含该触发器的离线版本后，系统才创建部署实例并按间隔探测；同一触发器版本不得被重复部署并产生双重探测。

### 9.1 目录树交互

- 左侧任务目录采用紧凑树形结构，一行只展示一个文件夹或任务，不展示版本详情、说明和行内操作按钮。
- 文件夹支持多级嵌套、展开和收起；目录数据较多时在固定高度内滚动，不得撑高整个页面。
- 单击任务名称直接打开任务；当前任务使用轻量选中态标识。
- 不展示“最近打开的任务”重复树，避免同一任务同时出现多次。
- 文件夹使用文件夹图标，任务使用流程节点图标，层级使用缩进和连接线表达。

### 9.2 右键菜单

- 新建、重命名、复制、移动和删除等管理操作只通过右键菜单展示，不直接占用目录树行宽。
- 在目录空白处或默认文件夹右键：新建任务、新建文件夹。
- 在普通文件夹右键：新建任务、新建子文件夹、重命名、移动目录、删除。
- 在任务右键：打开、重命名、复制、移动目录、删除。
- 无设计权限的用户不得看到修改类菜单，只允许打开任务。
- 支持鼠标右键以及键盘 `ContextMenu` / `Shift+F10`，点击空白处或按 `Esc` 关闭菜单。

### 9.3 数据治理规则

- 任务可以移动到任意有效文件夹，也可以移回根目录。
- 文件夹可以移动到其他文件夹或根目录，但禁止移动到自身或自身后代目录。
- 仅空文件夹允许删除；存在子文件夹或任务时必须先移动或删除其内容。
- 删除任务采用归档语义，保留历史运行记录，并自动停止其上线调度。
- 复制任务时复制最新设计为新的开发版，不复制历史运行记录、不复制上线状态、不启用调度。
- 从生产版本复制到开发版时移除生产 SM4 快照，后续提交上线时重新冻结当时绑定的最新 SM4 修订。

### 9.4 调度计划管理

- 任务定义、调度计划和运行实例必须分别展示：开启调度后立即形成可查询的调度计划，到达执行时间后才生成运行实例。
- 离线开发提供独立“调度管理”视图，统一展示 SM3、SM4、Doris SQL 及组合流程，不再跳转到 SM4 调度中心。
- 调度列表展示任务及目录、上线版本、调度规则、状态、下次执行时间、最近运行结果和更新时间。
- 调度状态包括：等待调度、排队中、运行中、未启用和异常。未到执行时间不得显示为“排队中”。
- 支持搜索和状态过滤，并提供打开任务、编辑调度、立即运行、停用/启用和查看日志操作。
- 左侧任务树为已启用调度的任务显示时钟标识，悬停展示下次执行时间。
- 停用调度只阻止未来自动触发，不删除历史运行记录，也不影响已经生成的运行实例。
- 上线版本冻结流程节点、连线和组件任务快照，但允许独立修改调度周期、执行时间、日/周、间隔和启用状态；保存后必须立即按新规则重算下次执行时间。
- 保存启用调度后必须明确提示计划已进入调度管理及下次执行时间。

### 9.5 画布自动排布

- 离线开发的可编辑开发版本提供“自动排布”操作；上线模式和只读版本不得修改节点坐标。
- 自动排布按节点依赖从上到下分层，同一层的分支横向展开，汇聚节点进入后续层级。
- 互不相连的流程按独立组件分组排列；没有依赖边的孤立节点在已连接流程之后按网格排列。
- 环形依赖需要按强连通组稳定排列，不能因为拓扑排序无法完成而遗漏节点、生成无效坐标或发生重叠。
- 排布结果必须确定：相同节点顺序和依赖关系重复执行时产生相同坐标，便于审阅和版本比较。
- 节点间距按可展开控件的保守高度预留；画布宽度和高度根据节点实际边界自动扩展，窄屏继续使用滚动容器，不压缩节点导致文字或连线重叠。
- 连线端点按节点实际渲染尺寸计算；正常上下游使用上下端点，环或同层回边使用左右端点。
- 自动排布成功后立即保存当前开发版本，并明确提示“画布已自动排布并保存”；保存失败不得显示成功提示。
- 画布坐标只属于展示状态，不纳入 `execution_content_hash`，不得因为自动排布产生新的业务内容版本。

### 9.6 离线画布节点与连线编辑

- 节点悬停或选中时显示白底蓝边输入/输出端口，从输出端口拖动到目标节点建立有向连线。
- 节点支持单击选中后按 `Delete` 删除，右键提供复制、编辑、重命名和删除；双击节点进入业务配置。
- 连线支持单击选中后按 `Delete` 删除，也可通过右键菜单删除。
- 后端和前端统一拒绝不存在端点、自环、重复边和环路。
- 离线流程允许多个根节点和多个已连接的独立分支；多节点流程中完全没有入边或出边的普通节点视为游离节点，醒目标红并禁止保存。
- 已发布的自包含数据变化触发器在离线画布中允许独立存在，因为该节点按设计禁止连接外部上下游。
- 本地节点、坐标或连线发生变化后标记编辑器为未保存；同一版本的异步刷新不得覆盖本地修改，保存成功或明确切换流程/版本后才重新加载服务器内容。

## 10. 数据连接与导入前检查

数据连接需要区分两层能力：

1. 数据库连接测试。
2. 文件服务器或 Docker 宿主机测试。

Oracle 场景尤其需要拆清楚：

- 数据库账号密码用于连接 Oracle。
- 服务器 SSH 账号密码用于访问 DMP 文件所在服务器或 Oracle Docker 宿主机。
- DMP 文件所在服务器不一定等于 Oracle 数据库服务器。

2026-07-13 已增强 Oracle 数据连接测试：页面会分别展示数据库连接、服务器 SSH、容器运行/健康状态；如果服务器信息未填写，会明确显示“已跳过”，不再只给一句笼统测试结果。

建议页面和接口拆分：

- 测试数据库连接。
- 测试 SSH 连接。
- 测试 DMP 目录权限。
- 测试 Oracle 容器状态。
- 测试宿主机 Python 3.7+。
- 测试 PDB 可用性。

任务执行前应统一做 preflight，并给出可读的检查结果。

## 11. 权限与审计

系统已有 RBAC 能力，后续高风险模块应继续细化权限点。

建议：

- 批量授权查看：`batchAuthorization:read`
- 批量授权维护：`batchAuthorization:manage`
- 批量授权导入：`batchAuthorization:import`
- 批量授权执行/下线/延期：`batchAuthorization:execute`
- SM4 密钥函数管理：独立高风险权限点。
- Oracle 自动导入 execute：独立高风险权限点。
- 数据库清理：独立高风险权限点。

审计要求：

- 谁上传文件。
- 谁执行授权。
- 谁执行下线。
- 谁刷新 SM4 密钥。
- 谁执行 Oracle 导入。
- 执行前参数摘要。
- 执行后结果。

## 15. 2026-08-06 批量授权共享权限租约闭环

### 15.1 背景与目标

同一 Doris 用户可能在不同授权批次、不同有效期内重复获得同一张源表的 `SELECT` 权限。现有批次级字段能够在前一批次下线时识别其他有效引用并跳过 `REVOKE`，但后一批次会把已经存在的权限记录为“外部既有权限”，导致最后一个批次结束后无法判断该权限最初是否由本系统创建，系统创建的权限可能永久残留。

本轮目标是在不改变批量授权页面、接口 URL、导入文件和批次明细响应契约的前提下，引入跨批次共享的权限租约，确保：

- 任一有效批次引用权限时，该权限持续存在。
- 最后一个有效引用结束后，只回收本系统最初创建的权限。
- 系统接管前已由外部授予的权限永不自动回收。
- 手动下线与定时到期使用相同的租约判断语义。

### 15.2 权限唯一键与租约模型

权限租约唯一键固定为：

```text
Doris connection_id
+ db_user_identity
+ source_database
+ source_table
+ privilege_type
```

部门、批次名称和导入文件名不参与权限唯一性判断。新增 `batch_auth_privilege_leases` 台账，至少记录：

- 权限唯一键各字段。
- `baseline_existed_before_system`：系统首次接管时权限是否已存在。
- `owned_by_system` / `ownership_state`：权限属于系统创建、外部既有或历史归属未知。
- `grant_owner_batch_id`：首次创建权限的批次。
- `state`：`active`、`revoked` 或 `error`。
- 最近检查、授权、回收时间及错误信息。

`batch_auth_grant_users.lease_id` 指向共享租约，每条批次用户明细即一条租约引用。数据库使用五段业务键规范化后的 SHA-256 `lease_key_hash` 建立唯一约束，避免 `utf8mb4` 长字段复合索引超过 MySQL 3072 字节限制；授权和回收更新需在事务中锁定租约，避免并发批次重复创建或提前回收。

### 15.3 授权规则

1. 对权限唯一键读取并锁定租约。
2. 租约不存在或已回收时，检查 Doris 当前实际权限：
   - 权限已存在：创建/恢复为 `external` 租约，不重复 `GRANT`。
   - 权限不存在：执行 `GRANT`，创建/恢复为 `system` 租约。
3. 已存在有效 `system` 租约时，后续批次只新增引用，不得把权限改判为外部既有。
4. 已存在有效 `external` 租约时，后续批次只新增引用，不得取得其回收所有权。
5. 若有效租约与 Doris 实际权限不一致，应重新检查并修复系统租约权限；失败必须记录为明细失败，不得生成成功引用。

### 15.4 手动与定时回收规则

1. 下线当前批次时，先结束当前批次对租约的引用。
2. 若仍有其他未下线且未到期的有效批次引用，记录 `skip_referenced`，不执行 `REVOKE`。
3. 若已无有效引用且租约为 `system`，执行 `REVOKE`，租约标记为 `revoked`。
4. 若已无有效引用且租约为 `external`，记录 `skip_existing`，不执行 `REVOKE`。
5. 若租约归属为 `unknown`，默认记录 `skip_ownership_unknown` 并保守跳过，禁止自动回收。
6. 手动下线和定时到期必须调用同一套租约决策函数；执行失败时保留 `failed` 状态和具体 SQL 错误，允许后续重试。

### 15.5 历史兼容与边界

- 新版本上线前的历史授权明细没有可靠的跨批次所有权证据，不得仅凭 `privilege_existed_before=true` 自动认定为外部权限，也不得仅凭 `granted_by_this_batch=true` 自动认定当前权限仍由系统持有。
- 历史明细首次参与回收且没有租约时创建 `ownership_state=unknown` 租约，默认不自动 `REVOKE`；新版本之后创建的批次进入完整租约闭环。
- 保留现有 `privilege_existed_before`、`granted_by_this_batch`、`revoke_decision` 等字段用于兼容展示和审计，但最终回收决策以租约为准。
- 不改变批量授权初始化、部门映射、Excel 模板、授权批次列表、详情、延期和下线 API 的请求结构。
- 本轮仅影响批量授权模块，不修改数据空间开通、资源权限、接口编排或其他模块的授权语义。

### 15.6 验收标准

使用隔离 Doris 用户、数据库和源表，在 `192.168.150.128` 完成真实验证：

1. 外部既有权限：授权批次创建和下线后权限仍存在。

3. A/B 重叠批次：A 创建权限，B 复用；A 先下线后权限仍存在，B 最后下线后权限被回收。
