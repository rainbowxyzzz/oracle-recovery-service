# 按 Doris 用户名找回审批授权默认密码

将 `scripts/find-approval-doris-password.sh` 单独上传到运行本应用的 Linux 服务器即可；完整包根目录也提供同名脚本。无需升级应用、修改 `.env`、安装宿主机 Python 或重启服务。

```sh
sh ./find-approval-doris-password.sh '张三_1234_1016'
```

若 API 容器改过名称，在第二个参数填写实际名称：

```sh
sh ./find-approval-doris-password.sh '张三_1234_1016' '你的API容器名'
```

传入纯用户名，不加 Doris 的 `'user'@'%'` 身份包装。用户名按完整文本、大小写精确匹配。可通过 `docker ps --format '{{.Names}}'` 查看容器名；执行者需要 Docker 管理权限。

## 输出含义

脚本读取成功内部授权日志里的用户名，关联审批授权任务，只解密对应任务当前保存的默认密码。输出任务名称、配置 ID、Doris 连接 ID、配置更新时间和候选密码。同名用户关联多个任务或连接时分别显示，不随意选择其中一项。

密码按 JSON 字符串显示：外层双引号不是密码；例如 `"abc"` 的实际密码为 `abc`，反斜线、换行和双引号按 JSON 转义表示。结果包含明文，请在受控终端查看，避免重定向到公共日志。

## 无法恢复的情况

- 默认密码曾被覆盖：当前配置不是历史密码，需查当时的系统 MySQL 备份及原凭据密钥。
- 用户创建前已存在或曾在 Doris 外部改密：当前配置不能证明其实际密码；脚本不尝试登录，避免触发失败计数。
- 成功日志或配置已删除、用户并非由审批授权创建：不按姓名或日期猜测关联，也不遍历返回其他任务密码。
- 凭据密钥错误或丢失：不把未解密的密文当密码返回。不要通过覆盖 `CREDENTIAL_ENCRYPTION_KEY` 来试错。

脚本只执行系统库 SELECT，不连接 Doris，不写文件或数据库，不修改用户、权限、密码或审批状态。

退出码：`0` 为所有匹配配置读取成功（不代表 Doris 登录验证成功），`2` 参数错误，`3` 未匹配记录，`4` 至少一个匹配配置无法解密/未设置密码，`5` 查询异常；Docker 自身错误沿用 Docker 退出码。
