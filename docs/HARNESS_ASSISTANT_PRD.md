# Harness 数据智能助手 PRD

## 2026-08-31 已确认需求与边界

用户用中文指定某个原始 DMP 并要求更新 DWD。助手识别已有处理路径，生成可审核计划，确认后调用既有 Oracle 恢复、数据同步、Doris SQL 生产工作流、SM4 能力。最后一步严格执行所选“全库加密任务”保存的表、字段和输出策略，不按血缘推断另一组加密对象，不自动换密钥。

本地最新源码（含 CSV 与 Oracle TEMP 修复）是开发基线，不用历史部署包覆盖源码。128 在 20260831 审计中存在 Worker 版本差异，最新完整包是独立构建版本；本轮不修改 128。新逻辑只对助手产生的批次启用，旧流水线、任务编辑、调度与血缘反推能力保持原行为。

## 业务规则

1. Harness 是自然语言规划层，不是数据库执行器；后端提供受控元数据和执行能力，模型不得获得数据库密码、种子、业务行数据或任意命令执行工具。模型服务地址、模型、凭据由部署配置提供；无真实配置明确报告未启用，不以规则匹配冒充 Harness。
2. 第一版只匹配管理员已配置的流水线（恢复模板、同步任务、标准化生产版本、标准目标、全库 SM4 任务均完整）。可按中文名称/业务域/目标库表推荐；缺少绑定、多个候选或未知 DMP 必须提示配置/选择，不能自动创建 SQL 或猜测库表。页面提供明确选择路径和文件的补充入口。
3. 自然语言与显式选择只生成草案。计划列出指定文件、Oracle 目标连接、ODS 表映射、DWD 生产版本、写入策略、全库 SM4 表/字段/输出策略与破坏性影响；用户点击确认后才允许运行。第一次允许管理员操作，跨模块授权不降级为普通聊天权限。
4. 文件限定在恢复模板目录中，通过真实文件清单解析，禁止模型提交任意主机、目录或通配符来扩大范围。分卷组必须明确完整文件清单；至少两次大小/mtime 观测并满足稳定等待后才恢复。草案源文件发生变化须重新规划。
5. 每个计划拥有独立持久化身份、确认哈希、操作者、四阶段运行 ID 与时间线。重复确认不重复恢复；同一文件/处理路径已有批次时返回已有运行或阻断。源文件与当前任务内容确认前发生变化时旧草案失效。
6. 计划绑定同步配置快照、生产工作流内容哈希与 SM4 任务修订快照；运行过程中编辑原 SM4 任务不得改变本次范围。密钥按 SM4 批次创建时当前成功部署版本绑定，沿用原有运行屏障与审计。
7. 上游真实成功后才能进入下一步；恢复结果必须有真实目标 Schema。同步继续采用已有恢复任务连接上下文与 Stream Load 路径，不猜测新的 Oracle 用户。DWD 只执行已上线的 SQL 工作流，不能把任意开发草稿当作标准化生产版本。
8. 长任务由已有后台调度与 Worker 执行，不依赖聊天窗口存活。外部派发前记录提交状态；响应丢失或崩溃造成结果未知时阻断并显示待核对，不自动重复写入。失败阶段允许明确人工核对后继续，保留成功阶段和失败历史；不得声称跨 Oracle/Doris 是同一事务。
9. 计划/状态/元数据仅向管理员开放。模型输出、文件名、库表注释及日志视为数据，不能作为授权来源；浏览器展示使用纯文本。Harness 单独隔离运行且固定发布版本，默认禁用 Shell、文件编辑与其他无关工具。运行时与公开主分支 API 不一致时，以实际安装版本为准并记录。

## 触达路径与验收

- 页面：新增独立智能助手页面，主界面增加入口；不重排已有业务表单。
- API：助手目录/规划/计划详情/确认/继续；复用登录管理员校验，所有写入校验哈希、状态与对象。
- 保存：新增助手计划元数据；旧数据表字段不删改，原任务不回写。
- 执行：助手批次专属推进逻辑，复用 Oracle 队列、同步 Worker、生产工作流、SM4 快照执行函数。
- 日志：总进度与四阶段 ID、明确失败/未知状态，可从旧运行模块核对详细日志；不向模型传输原始运行日志或凭据。
- 打包部署：仅提供依赖/配置说明及受影响文件清单，本轮不打完整包、不发布、不迁移远端数据。
- 回归：先测试计划匹配/权限/文件越界/内容变更/确认幂等/全库范围快照，再模拟四阶段推进、任务失败与未知提交、密钥函数未被调用。运行原流水线和同步/SM4/生产版本相关回归，检查新增页面的保存/回读、错误及窗口布局。
- 验证口径分开记录：纯本地自动化、模拟 Harness、真实 Harness 运行时、真实模型及 128 业务链路。未完成的验证不标通过。

## 2026-08-31 发布验证授权

用户已明确要求发布并功能测试，本轮采用模式二：备份后最小热更新 API、Data Sync Worker 和 Data Platform Worker，只创建隔离测试对象，不重启 Doris 或业务数据库，不更新无关 Worker，不打完整包、不提交 GitHub。当前128实测 Docker 为1.13.1，必须按实际版本校验。未配置真实模型时，不伪造自然语言通过结果；业务四阶段可以显式确认隔离计划完成真实测试。模型桥接镜像必须保持独立且不携带应用凭据，不能直接复用含生产环境变量的应用提交镜像作为规划器。旧Docker拉取运行时失败时应记录限制，不降低隔离要求。
