# Doris CSV 导入任务化解析 PRD

更新日期：2026-08-10

## 1. 背景

当前 Doris CSV 导入使用同步 `preview` 接口完成多文件解析。文件数量多或单文件较大时，页面会长时间无反馈，用户无法判断上传、解析、结构校验和保存结果的进度，也无法在发现选错文件后安全停止。多文件导入同一张表时，每个文件都完整推断结构，造成重复解析和重复建表判断。

## 2. 目标

本次改造在 Doris CSV 导入模块内新增任务化解析能力：

- 点击“解析文件”后立即创建解析任务，并弹出进度窗口。
- 解析过程按上传、解析、结构校验、问题行统计、保存结果分阶段展示百分比。
- 支持停止解析任务，停止采用协作式标记，不粗暴终止进程。
- 支持“多个文件合并导入同一张表”和“多个文件分别导入多张表”两种模式。
- 页面刷新后可以通过任务 ID 恢复最近解析任务状态。
- 解析成功后继续复用现有 Stream Load 导入能力，不改变旧的单文件导入路径和 Doris 连接配置。

## 3. 导入模式

### 3.1 多文件合并到同一张表

- 第一个文件完整解析表头、字段类型、目标表和字段映射。
- 后续文件复用第一个文件的目标表和字段结构。
- 后续文件只做轻量校验：编码、CSV 格式、列数、表头兼容性、类型兼容性、有效行和问题行统计。
- 目标表只创建或覆盖一次，后续文件按相同字段顺序 Stream Load 到同一目标表。
- 勾选包含表头时，后续文件如果首行与标准表头一致，或仅存在大小写和空格差异，应跳过表头；不一致但数据列数匹配时按无表头数据处理，并记录警告；无法判断时标记为失败或需要人工确认。

### 3.2 多文件导入多张表

- 每个 CSV 独立解析。
- 每个文件独立生成字段结构、目标表和字段映射。
- 每个文件独立建表和 Stream Load。
- 每个文件拥有独立状态、统计、问题行样例和导入结果。

## 4. 状态与进度

解析任务状态：

```text
created
uploading
queued
parsing
validating
completed
failed
stopping
stopped
```

文件节点状态：

```text
waiting
parsing
succeeded
failed
waiting_import
importing
imported
import_failed
stopped
```

进度权重：

- 上传/登记文件：20%
- CSV 解析：50%
- 结构/类型处理：15%
- 问题行统计：10%
- 保存结果：5%

页面需要展示：

- 总体进度。
- 当前文件名。
- 当前阶段。
- 已完成文件数和总文件数。
- 已处理字节数和总字节数。
- 有效行数和问题行数。
- 当前任务状态。

## 5. 页面交互

- 点击“解析文件”后显示模态进度弹窗。
- 解析未结束时禁止再次解析、确认导入、切换文件来源、切换 Doris 连接、切换导入模式和表头策略。
- 弹窗关闭按钮在解析中不能只是隐藏，应先弹出确认。
- 确认停止后任务进入 `stopping`，后台在当前文件块处理边界检查停止标记，完成当前安全点后变为 `stopped`。
- 已完成文件的解析结果保留，未开始或未完成文件标记为 `stopped`。
- 任务完成、失败或停止后，弹窗允许关闭，解析结果区域展示文件级结果。
- CSV 解析进度弹窗必须使用稳定尺寸，不得随文件节点数量无限增高。桌面端弹窗宽度以 720px 为上限，高度按黄金比例约束为宽度的 0.618 倍，并受视口高度限制；窗口缩小时保持在可视区域内。
- 文件节点数量较多时，只允许文件节点区域内部滚动或折叠展开，弹窗标题、进度、汇总指标和停止/关闭按钮必须保持可见。

## 6. 后端接口

保留历史接口：

- `POST /api/v1/doris-csv/preview`
- `POST /api/v1/doris-csv/import`
- `POST /api/v1/doris-csv/ftp/preview`
- `POST /api/v1/doris-csv/ftp/import`

新增任务接口：

- `POST /api/v1/doris-csv/parse-tasks`
- `GET /api/v1/doris-csv/parse-tasks/{task_id}`
- `POST /api/v1/doris-csv/parse-tasks/{task_id}/stop`

第一阶段实现允许 API 进程创建后台解析任务并将进度持久化到系统库；后续如 CSV 导入量继续增加，可把同一执行函数迁移到独立 Celery Worker 和独立队列，不改变前端 API 契约。

## 7. 持久化内容

解析任务至少保存：

- 任务 ID、Doris 连接 ID、目标库、来源、导入模式、分隔符、编码、表头策略。
- 总文件数、已完成文件数、总字节数、已处理字节数、总体进度、当前阶段、当前文件。
- 停止标记、错误信息、创建/开始/完成时间。

文件节点至少保存：

- 文件名、文件大小、目标表名、状态。
- 总行数、有效行数、问题行数。
- 前 20 行样例。
- 前 200 行类型推断样本或字段推断摘要。
- 字段映射、问题行样例、警告信息。

## 8. 兼容性边界

- 不删除历史同步 `preview/import` 接口，避免旧页面或外部调用中断。
- 不改变现有 Doris Stream Load 认证、HTTP 端口、`Expect: 100-continue`、中文字段和反引号字段处理策略。
- 不改变数据同步模块、SM4 模块、接口编排模块和批量授权模块。
- 第一阶段本地上传文件暂存于应用数据目录，任务结果保存在系统元数据库；后续独立 Worker 化时保持接口响应兼容。

## 9. 验收标准

在 `192.168.150.128` 完成真实验证：

1. 本地上传两个 CSV，选择“合并到同一张表”，只以第一个文件生成表结构，两个文件导入同一个 Doris 目标表。
2. 本地上传两个 CSV，选择“分别导入多张表”，每个文件生成独立目标表并导入成功。
3. 文件解析期间页面显示进度弹窗，按钮禁用，完成后恢复可操作。
4. 停止解析任务后，任务状态变为 `stopped`，未完成文件标记停止，已完成结果保留。
5. 含中文字段、中文表名或特殊字段名的 CSV 可以完成 Stream Load。
6. 空文件、列数不一致、编码错误、表头不一致时返回明确文件级错误或警告。
7. 发布后 API/Worker 健康、近期错误日志和队列状态无新增异常。
8. 上传 100 个以上 CSV 时，解析进度弹窗不占满窗口，文件节点在弹窗内部滚动查看，停止和关闭按钮始终可点击。

## 10. 解析完成后的导入确认弹窗

解析任务完成后，用户点击“确认导入”不得使用浏览器原生 `window.confirm`。系统应使用与“CSV 解析进度”一致的页面内弹窗风格，避免不同浏览器原生确认框造成视觉和交互不一致。

- 弹窗沿用解析进度弹窗的稳定尺寸约束：最大宽度 `720px`，高度按宽度的 `0.618` 倍约束，并受视口高度限制。
- 弹窗使用统一的标题栏、状态徽标、内容区和底部操作区。
- 内容区展示目标库、导入文件数量、导入模式、覆盖策略和文件到目标表的映射摘要。
- 文件数量较多时，文件摘要在弹窗内容区内部滚动，不能撑大弹窗或遮挡确认、取消按钮。
- “继续导入”提交导入请求并关闭确认弹窗；“取消”只关闭弹窗，不发起导入请求。
- 本次只调整 Doris CSV 前端交互，不改变既有 `preview/import` 接口、Stream Load 语义、字段映射和导入结果处理。

验收至少覆盖：解析成功后打开确认弹窗、取消不发请求、继续导入正常提交、覆盖提示正确显示、100 个以上文件时弹窗不溢出且按钮可见。

## 11. 确认导入大规格提交限制修复

2026-08-10 现场发现：解析 100 个以上 CSV 后点击“确认导入”，当前页面会把完整 `dorisCsvPreviewData.files` 作为 `table_specs_json` 的单个 `multipart/form-data` 字段提交到同步导入接口。该对象包含样例行、问题行、目标字段、字段类型和提示信息，文件多或字段多时容易超过 Starlette/FastAPI 默认单个 multipart part 约 1MB 的限制，接口在进入业务代码前返回 `Part exceeded maximum size of 1024KB`。

临时止血要求：

- 前端导入阶段不得提交完整预览对象，只提交导入必需字段：文件名、目标表名、表头策略、字段原名、目标字段名、字段类型、是否可空和最大长度。
- 本地上传导入接口继续兼容历史 `table_specs_json` 字段，同时新增 `table_specs_json_parts` 分片字段；当轻量规格仍然较大时，前端按小块拆分为多个 part，后端按顺序拼接。
- FTP 导入的 JSON 请求体也复用轻量规格，降低请求体和日志体积。
- 本次修复不改变现有同步导入语义、不改变 Stream Load 参数、不引入新的导入任务表。

后续完整改造要求：

- 确认导入应基于 `parse_task_id` 创建导入任务，后端直接读取已持久化的解析结果和暂存文件，不再重复上传 CSV 文件，也不再通过表单字段回传大型规格 JSON。
- 导入任务应具备任务列表、文件节点、总体进度和日志能力，页面刷新后可继续查看后台状态。
## 12. 导入任务化落地补充

2026-08-10 起，本次确认导入进一步收敛为“解析任务驱动导入”：

- 本地 CSV 解析完成后，前端只保存当前解析任务 ID 和已编辑的单文件映射；确认导入时只提交 `parse_task_id`、`create_table` 和 `overwrite` 等轻量参数。
- 后端确认导入阶段从解析任务的持久化文件和文件级预览中读取字段映射，不再依赖前端回传整包预览 JSON。
- 解析任务继续承担上传、解析、结构预览和文件级配置保存；导入阶段在同一任务记录上进入 `waiting_import / importing / imported / import_failed` 等状态。
- 每个任务需保留文件级状态、总体进度和日志列表，页面刷新后可继续查看解析与导入两个阶段的执行结果。
- 历史 `preview/import` 和 FTP 同步导入能力继续保留，作为兼容路径，不作为本次大规格修复的主路径。

## 13. 2026-08-11 交互闭环补充

本次继续收口 Doris CSV 导入模块中尚未完全闭环的三项交互，不改变既有 `preview/import`、FTP 路径、Stream Load 语义、任务持久化结构和日志结构。

1. 点击“解析文件”后，页面必须立即出现进度弹窗，不得等待创建任务接口完成后再展示。
2. 解析与导入都应使用同一个任务弹窗，任务创建中、上传中、解析中、导入中都要给出明确阶段文案。
3. 任务刷新后仍应能通过任务列表和日志查看执行状态。
4. 预览字段映射默认值必须优先显示源字段名，不得因为目标表字段列表不匹配而自动置空。
5. 目标库输入必须支持候选下拉，同时保留手动输入兜底；候选读取失败不能阻断用户继续填写。

验收补充：
- 大文件或多文件点击“解析文件”后，进度弹窗应在任务创建前可见。
- Doris 连接切换后，目标库候选应重新加载。
- 字段映射默认值、文件表名和任务结果在刷新后保持一致。

## 14. 2026-08-11 GB18030 文件编码选项

Doris CSV 导入页面的文件编码下拉框新增 `GB18030` 选项。该改动仅增加前端可选值，后端仍沿用既有 `charset` 字符串参数和 Python codec 解码能力，不改变 `preview/import` 接口、任务化解析、FTP 路径、字段映射、CSV 重新生成和 Stream Load 语义。导入阶段仍会把有效数据重新输出为 UTF-8、全字段双引号包裹的 CSV 后提交给 Doris。

## 15. 2026-08-12 同表多文件字段映射与中文表头规则

当导入模式为“多个文件合并导入同一张表”时，页面只展示一套目标表结构和字段映射，该映射以第一个成功解析的基准文件为准；后续文件仅展示文件节点、表头匹配状态、行数、问题行和将写入的同一目标表，不再重复展示或编辑各自字段映射。

字段映射编辑规则：
- 修改目标表名时同步到同一任务的全部文件。
- 修改基准文件字段映射时，同步到全部后续文件的持久化预览，确保导入阶段使用同一套目标列。
- 后续文件表头与基准表头一致时跳过表头并复用基准字段结构；表头不一致或列数不一致时给出明确文件级错误，不生成误导性的重复字段提示。

中文字段规则：
- CSV 表头中的中文字段名默认保留为目标字段名，Doris DDL 和 Stream Load 继续通过反引号或列清单处理，不再把中文表头清洗成 `csv_table`、`csv_table_2` 等无意义字段。
- 仅当字段名为空、包含 Doris 标识符不宜直接使用的控制字符或与同文件其他字段真实重名时才做兜底重命名，并保留清晰提示。

## 16. 2026-08-12 解析后选择目标库的导入闭环

用户允许先选择 CSV 文件并执行解析，在解析完成后再选择或修改目标库。确认导入时，前端必须把当前页面目标库提交给任务化导入接口；后端在启动导入前将该目标库写回解析任务，并以该值作为建库、建表和 Stream Load 的目标库。若确认导入时目标库仍为空且连接也没有默认库，必须返回明确的缺少目标库错误。

该改动只影响任务化解析后的确认导入路径，不改变历史同步 `preview/import` 兼容接口、FTP 兼容导入、字段映射、CSV 重新生成和 Stream Load 参数。任务列表、导入确认弹窗和运行日志展示的目标库应与最终后端执行目标库一致，避免解析阶段旧目标库或连接默认库覆盖用户后选目标库。
## 17. 2026-08-12 CSV 文件级自动识别编码

当一次 Doris CSV 导入选择的多个文件可能混合 UTF-8、GBK、GB18030 等编码时，页面不应强制用户在解析前为整批文件选择同一个固定编码。文件编码策略调整为：

- 页面“文件编码”默认提供“自动识别”，同时保留 `UTF-8 / 带 BOM`、`UTF-8`、`GBK`、`GB18030` 手动选项。
- 当选择“自动识别”时，解析阶段按文件独立识别编码，不再把任务级编码硬套到所有文件。
- 识别优先级为：带 BOM 的 `UTF-8-SIG`、普通 `UTF-8`、`GB18030`、`GBK`；中文兜底优先使用 `GB18030`，因为其兼容 GBK 且字符范围更完整。
- 每个文件的识别结果必须写入文件级预览 JSON，并在解析日志、进度文件节点和字段预览区域展示，便于用户判断混合编码文件的处理情况。
- 手动选择固定编码时保持旧语义：整批文件仍使用用户指定编码；若某个文件不符合该编码，应给出文件级错误。
- 导入阶段不得重新猜测编码，应优先复用解析阶段保存的文件级识别结果；旧任务或旧接口没有文件级编码信息时，才回退任务级 `charset`。
- 多文件导入同一表时，仍只展示一套字段映射，但后续文件也必须独立识别编码并显示文件节点编码。
- 本需求不改变建库、建表、字段映射、CSV 重新输出为 UTF-8、Stream Load 参数和历史 `preview/import`、FTP 兼容接口的业务语义。

## 18. 2026-08-19 中文映射字段 Stream Load 编码修复

现场发现：CSV 解析和建表均成功，但当映射后的目标字段名包含中文时，导入阶段在发送 Doris Stream Load 前报 `'ascii' codec can't encode characters`。原因是当前实现把目标字段名直接写入 HTTP `columns` Header，`httpx/httpcore` 按 ASCII 序列化 Header，请求尚未到达 Doris 就失败。

修复规则：

- 目标字段名全为 ASCII 时，继续使用现有 `format=csv`、`columns` Header 和 `skip_lines=1`，不改变英文字段及旧接口语义。
- 任一目标字段名包含非 ASCII 字符时，使用 Doris `format=csv_with_names`，由 Doris 从已重新输出为 UTF-8 的 CSV 首行读取目标字段名；不再发送含 Unicode 的 `columns` Header，也不再叠加 `skip_lines`。
- CSV 首行继续由当前字段映射生成，因此字段改名、重排和子集导入语义保持不变。
- 新建表和已有表都必须覆盖；不得为规避编码异常而删除字段映射或强制将中文字段重命名为英文。

验收要求：

1. 纯英文映射仍使用原 `columns` Header 并导入成功。
2. 中文及中英文混合映射不再触发 ASCII 编码异常，Stream Load 导入成功。
3. 中文字段改名、顺序调整和字段子集导入后，Doris 表中列与数据对应正确。
4. Stream Load 请求所有 Header 值都可以按 ASCII 序列化。
5. 在 `192.168.150.128` 使用隔离库表完成真实中文映射导入，并回归英文映射路径。

## 19. 2026-08-26 CSV 字段类型自定义与批量 VARCHAR

现场发现：当 CSV 前部样本均为整数、但后续行出现字符串时，自动推断可能把字段识别为 `BIGINT`，Doris Stream Load 会把后续不兼容值过滤，造成用户看到的导入数据缺失。自动推断只能作为默认建议，不能替代用户对目标表结构的最终确认。

本次增加以下能力：

- 解析完成后，每个映射字段同时展示可编辑的 Doris 目标类型；修改后与字段名映射一起保存到解析任务的文件级预览，刷新或重新进入任务后仍能回读。
- 页面提供常用类型候选，并允许用户手动输入受支持的标量类型。后端必须统一规范化并校验类型，禁止把任意字符串直接拼入 DDL。
- 首期允许 `BOOLEAN`、整数、浮点、`DATE`、`DATETIME`、`DATEV2`、`DATETIMEV2`、`STRING`，以及带合法范围参数的 `CHAR`、`VARCHAR`、`DECIMAL/DECIMALV3`；不开放 ARRAY、MAP、STRUCT、聚合类型或任意 SQL 片段。
- 每个文件结构编辑区增加“全部设为 VARCHAR(65533)”按钮。多表模式只修改当前文件；合并到同一表模式修改基准映射并同步到任务内全部文件。
- 修改字段类型不得改变源字段名、目标字段名、可空设置、样例值、问题行判定和 Stream Load 列顺序。
- 任务化导入在建表时读取已持久化的自定义类型；导入已有表时字段类型仍由已有 Doris 表结构约束，本次不自动 ALTER 已有表。
- Doris `DUPLICATE KEY` 建表仍沿用现有 Key 安全规则：当被选作 Key 的字段配置为超长 VARCHAR 时，该 Key 的实际 DDL 收窄为 `VARCHAR(255)` 并记录警告，其他字段保持用户配置。
- 历史 `preview/import`、FTP 同步导入、中文字段 `csv_with_names`、文件编码、任务状态和 Stream Load 参数语义保持兼容。

验收要求：

1. 混合数字和字符串的 CSV 可将目标字段改为 `VARCHAR(65533)`，保存回读后类型不丢失，导入时字符串行不再因整数类型而被过滤。
2. “全部设为 VARCHAR(65533)”在多表和同表模式下分别按上述作用域生效。
3. 合法类型可保存并进入建表 DDL；非法类型、越界长度和 SQL 片段由接口明确拒绝。
4. 回归自动推断、字段改名、中文映射、单表多文件同步、任务导入和历史兼容接口。
