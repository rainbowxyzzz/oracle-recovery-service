# 帮助与架构中心 PRD

## 1. 背景

系统模块、接口、任务、调度和运行链路持续增加，单一 Markdown 与原始 Swagger 只能分别回答“文字怎么写”和“接口怎么调”，无法让管理员快速理解功能用途、操作顺序、权限边界、数据影响及模块耦合关系。

## 2. 目标

- 在现有控制台新增“帮助与架构中心”，登录用户均可访问。
- 统一提供系统总览、功能手册、接口字典、耦合关系四类视图。
- 接口字典从运行中 `/openapi.json` 自动发现路径、方法、参数、请求模型和响应状态，避免接口新增后完全漏项。
- 业务中文含义、操作步骤、权限、影响范围、风险和依赖由受控知识目录维护，避免仅依据路径名称机械推断高风险语义。
- 支持模块、接口路径、中文名称和关键字搜索，并可按模块、HTTP 方法筛选。

## 3. 信息架构

### 3.1 系统总览

- 展示模块数、接口数、高风险模块数和运行架构层级。
- 说明 Browser/API、系统元数据库、Redis/Celery、独立 Worker、业务数据库之间的职责边界。
- 强调系统元数据库不是业务恢复目标库，任务定义、版本快照与实际运行相互隔离。

### 3.2 功能手册

每个模块至少包含：中文名称、用途、典型操作步骤、所需权限、读写影响、风险等级、上游依赖、下游影响及关联接口数量。

### 3.3 接口字典

每个接口展示：HTTP 方法、路径、中文含义、所属模块、OpenAPI 摘要、请求参数、请求体模型、响应状态和影响范围。接口说明不得展示 Token、密码、密钥种子、连接密码或真实请求数据。

### 3.4 耦合关系

- 以模块卡片和依赖连线/文字路径展示上游、下游关系。
- 高风险链路重点覆盖：数据连接→导入/同步/加密；密钥函数→SM4 任务→调度→离线开发；审批流→批量授权→外部系统；离线开发→组件→调度→Worker→日志。

## 4. 权限与安全

- “帮助与架构中心”属于只读公共模块，任何已登录用户可见，不新增业务操作权限。
- 页面只读取 OpenAPI 结构和内置知识目录，不读取业务表内容、运行请求体、日志详情、密钥或凭据。
- 接口入口继续遵守系统现有登录/API Key 鉴权；帮助页面不会绕过接口权限。
- 原 `/docs` 保留，作为面向开发人员的原始 Swagger 补充入口。

## 5. 兼容性边界

- 不修改现有接口路径、请求字段、权限模型、任务保存、调度、Worker 或数据库结构。
- 不改变已有主导航模块的显示权限；帮助中心仅对登录状态开放。
- 第一版知识目录随前端源码发布，不提供在线编辑，避免未经审批的文档内容直接进入生产。

## 6. 验收

- 登录后可进入帮助中心，四个视图可切换。
- 能搜索模块和接口，按模块及方法筛选。
- OpenAPI 新接口即使没有人工中文目录，也能以自动兜底说明展示。
- 功能手册明确展示操作、权限、影响和耦合信息。
- 页面在桌面最大化、半屏和窄窗口不横向溢出，接口列表和详情独立滚动。
- 原业务模块、Swagger `/docs`、接口鉴权和运行链路保持不变。

## 7. 风险

- 自动推断的中文说明只能作为兜底，不能替代高风险模块的人工业务知识；高风险模块必须维护明确目录。
- OpenAPI 中缺失的字段描述会影响接口可读性，后续应逐步补齐 Schema `description`。
- 模块耦合关系属于架构认知，不代表数据库事务边界；页面必须明确区分依赖关系与事务保证。
