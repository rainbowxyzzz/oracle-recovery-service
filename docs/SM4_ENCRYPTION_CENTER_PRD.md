# Doris SM4 加密中心 PRD

## 1. 产品定位

Doris SM4 加密中心是 SM4 数据加密的统一入口。对象选择、手动提交、单表加密、批量加密、定时计划、密钥函数、任务调度和执行审计都在同一业务模块内完成，避免功能割裂。

核心目标：

- 支持按库扫描表字段，并按敏感字段规则快速选择加密列。
- 支持单表、批量任务统一进入调度中心，再从已确认任务沉淀定时计划。
- 支持队列化执行、并发控制、任务停止、失败重试和全过程日志审计。
- SM4 密钥函数独立管理，加密任务只消费目标数据库当前已成功部署并验证的密钥版本。

2026-07-15 架构调整：原“自动快照加密”不再作为独立产品能力继续扩展，迁移为离线开发中的“数据变化触发器 + SM4任务组件”。触发器只保存监控条件，SM4组件只保存冻结的任务修订；历史自动快照任务、批次和审计记录继续保留。详细需求见 `docs/DATA_CHANGE_TRIGGER_AND_SYNC_PRD.md`。

## 2. 模块结构

左侧入口：

- Doris SM4 加密中心

模块内页签：

- 对象选择
- 任务调度
- 定时计划
- 密钥函数
- 文件脱敏/解密
- 执行日志

## 3. 对象选择

对象选择负责定义“加密什么”和“如何落地”。

能力包括：

- 选择 Doris 数据连接。
- 源数据库优先通过下拉框选择，列表来自 Doris `SHOW DATABASES`。
- 支持刷新源数据库列表。
- 默认过滤 Doris 系统库，包括 `information_schema`、`mysql`、`performance_schema`、`sys`、`__internal_schema`。
- 当权限不足或列表不完整时，允许用户选择“手动输入”作为兜底。
- 配置敏感字段关键词。
- 扫描库表字段。
- 默认按关键词匹配待加密字段，也允许手动勾选或取消字段。
- 单表点击“加密此表”提交单表批次。
- 多表勾选后保存为 SM4 任务，再从任务列表“执行一次”或绑定到离线开发调度。
- 选择目标表策略：
  - 追加到固定加密表。
  - 删除目标表后重建。
  - 自动新建版本表。
- 配置目标加密表后缀。
- 提交加密任务时不得自动创建、刷新或轮换 SM4 密钥；目标数据库没有可用密钥部署记录时应阻止提交并提示前往密钥函数页面处理。
提交后不在当前页面等待结果，而是创建调度任务并自动切换到“任务调度”页签。

### 3.1 已保存任务与编辑交互

- 任务名称是 SM4 任务定义的业务名称，不是别名，也不是离线开发版本名称。
- 新建任务时创建新的 `task_definition_id`，初始修订号为 `V1`。
- 编辑已有任务并点击“保存任务”时保持原 `task_definition_id`，内容发生变化时生成下一修订号。
- 编辑状态必须直接展示任务名称输入框，不在保存时再次通过弹窗询问名称。
- “保存任务”是编辑页面唯一主按钮，使用蓝色主按钮样式。
- 提供“另存为新任务”，用于生成新的 `task_definition_id`，避免影响原任务的开发引用。
- 编辑页面不展示“提交选中表批次”，防止用户误把一次执行理解为保存任务。
- 一次执行统一从已保存任务列表点击“执行一次”，执行时创建独立批次，不修改任务定义。
- 保存任务只持久化任务定义，不立即执行、不创建批次。

### 3.2 离线开发引用与生产快照

- 离线开发节点通过 `task_definition_id` 绑定 SM4 任务。
- 开发版展示任务当前名称和当前修订号，任务重命名后不得继续显示过期名称。
- 开发版提交为生产版本时，必须冻结 SM4 任务完整快照，包括连接、源库、表、字段、目标库、落地策略、目标后缀、任务名称和修订号。
- 已提交、已上线和已下线生产版本执行时只能读取冻结快照，禁止运行时读取任务定义的最新内容。
- 修改已被引用的 SM4 任务前，页面必须展示开发节点、生产节点、在线节点和在线流程范围。
- 修改任务后，已有生产版本继续运行旧快照；开发版重新提交并上线后才运行新修订。
- 新建开发版并绑定同一任务后，提交上线时冻结该任务当时的最新修订。
- 回滚旧生产版本时必须运行该版本原有快照，不能被后续任务修改污染。
- 旧版本升级到本能力后，在任务首次修改或删除前必须先冻结已有生产引用，保证兼容历史数据。

场景结果：

| 场景 | 运行结果 |
|---|---|
| 上线后直接修改并保存 SM4 任务，不重新提交离线版本 | 原在线生产版本继续运行修改前快照 |
| 修改后，从原开发版重新提交并上线 | 新生产版本运行修改后的修订 |
| 修改后，新建开发版并提交上线 | 新生产版本运行提交时绑定的最新修订 |

概念定义：

- 源数据库指源数据表所属的 Doris 数据库。
- 对象选择模块基于源数据库扫描表和字段。
- 源数据库本身不是被加密对象，被加密对象是其中被选择的表和字段。
- 当前版本加密结果表默认写回同一源数据库；如果后续支持跨库输出，应单独配置“结果数据库”或“目标数据库”，不得复用“源数据库”概念。

## 4. 任务调度

任务调度负责统一承接手动任务和定时计划触发的任务。

任务来源包括：

- 单表手动加密。
- 多表手动批量加密。
- 定时计划自动触发。
- 定时计划立即执行。
- 从历史任务复制生成。
- 从失败任务重试生成。

任务状态：

- queued：排队中。
- reserved：已派发，等待 Worker 接收。
- running：执行中。
- stopping：停止中。
- stopped：已停止。
- cancelled：已取消。
- succeeded：成功。
- partial：部分成功。
- failed：失败。

调度能力：

- 任务提交后先进入队列，不再由 API 请求线程直接执行。
- 后台调度器按固定周期扫描 queued 任务并派发给 Celery Worker。
- 支持全局 Worker 并发上限。
- 支持同一数据连接并发上限。
- 支持同一数据库并发上限。
- 支持同一连接、同一库、同一表维度的表锁，避免两个任务同时改同一张表。
- reserved 状态超时未被 Worker 接收时自动回到 queued。
- queued/reserved 任务可直接取消。
- running 任务可请求停止，并尽量中断正在执行的 Doris SQL。
- 停止 Doris SQL 时会尝试 `KILL QUERY`、`KILL CONNECTION`、`KILL`、`CANCEL QUERY` 多种方式。

页面能力：

- 查看任务列表和状态。
- 查看每张表的执行结果。
- 独立弹窗查看批次任务详情。
- 查看源表、目标表、字段、Doris 会话 ID、停止信息和错误信息。
- 停止或取消任务。
- 复制任务为新任务。
- 回填任务配置到“对象选择”页签。
- 将任务设置为定时计划模板。
- 按策略重试：
  - 只重试失败表。
  - 重试整个批次。

## 5. 定时计划

定时计划是任务调度下的“已确认任务模板 + 触发规则”能力。计划不再要求用户重新扫描库表或重新选择字段，而是从任务调度中的某个批次任务派生。

创建入口：

- 在任务调度列表中选择一个任务。
- 点击“设为定时计划”。
- 系统读取该任务的连接、源数据库、表清单、字段清单、落地策略和目标后缀。
- 用户只需要补充计划名称、周期、时间和启用状态。

能力包括：

- 基于已确认任务保存计划模板。
- 配置计划名称。
- 配置周期：
  - 每月。
  - 每周。
  - 每日。
  - 间隔分钟。
- 不同周期只展示和启用相关输入：
  - 每月：填写每月第几天和当天执行时间。
  - 每周：填写星期几和当天执行时间。
  - 每日：只填写每日执行时间。
  - 间隔分钟：只填写间隔分钟。
- 表单实时提示预计下次执行时间。
- 启用或停用计划。
- 编辑已有计划。
- 立即执行一次。
- 查看该计划触发出的历史批次。

规则：

- 定时计划的业务模板来自任务调度，不来自对象选择页的临时勾选状态。
- 停用计划只阻止未来自动触发。
- 已经生成的批次任务需要在“任务调度”页签单独停止或取消。
- 立即执行一次会创建新的批次任务，并自动切换到“任务调度”页签。
- 编辑计划不会影响已经生成的历史批次。

## 6. 密钥函数

密钥函数负责刷新 Doris 中的 `CQ_SM4_ENCRYPT` 函数。

能力包括：

- 选择 Doris 数据连接。
- 配置函数名。
- 选择密钥来源：
  - 自动生成随机密钥种子。
  - 手动输入密钥种子。
- 生成 UDF jar。
- 在 Doris 业务库中重建函数。
- 使用固定函数名执行 SQL 验证，验证通过后才认为函数已生效。
- 返回密钥指纹、jar 文件名、每个库的创建和验证结果。
- 密钥创建、轮换和函数部署通过密钥函数页面独立完成，不与任务保存、手动执行或调度执行联动。
- 对外函数名始终固定为 `CQ_SM4_ENCRYPT`。
- 系统内部使用版本化 UDF 实现并重新绑定固定函数名，避免覆盖同名 class 带来的缓存风险。
- 默认不重启 Doris 集群；验证失败时才提示人工检查或考虑 BE 重启。

约束：

- 密钥明文不在前端展示。
- 普通业务用户只调用 Doris 函数，不直接接触密钥。
- 密钥刷新失败或用户取消时，不继续提交加密任务。
- 如果未来改成固定 Java class 名并覆盖同名 jar，则可能需要重启 BE 才能重新加载 class，不符合当前“不默认重启、创建后验证”的策略。
- API 和 Worker 共享 `/app/data/sm4-jars` 持久卷，应用升级与容器重建不得删除历史活跃密钥 JAR。
- Doris 请求历史 JAR 而文件缺失时，服务根据系统库中 `jar_filename -> 活跃密钥版本` 关系自动重建同名 Java 8 JAR；找不到密钥记录或无法解密种子时返回可诊断错误。
- SM4 批次提交时主动补齐绑定密钥 JAR，批次执行前再次验证当前库固定函数与批次密钥一致。

## 7. SM4 固定函数名与换密钥生效逻辑

本模块必须同时满足两个要求：

- 业务用户和外部系统始终只调用固定函数名：`CQ_SM4_ENCRYPT(列名)`。
- 系统刷新密钥时默认不重启 Doris FE/BE。

为同时满足这两个要求，系统采用“固定对外函数名 + 内部版本函数 + Alias 绑定 + 创建后验证”的策略。

### 7.1 名称分层

- 对外函数名固定为：`CQ_SM4_ENCRYPT`。
- 内部真实 Java UDF 函数按密钥指纹生成版本名，例如：`CQ_SM4_ENCRYPT_3544254952094837`。
- jar 内部 Java class/symbol 同样按密钥指纹生成，例如：`CqSm4Encrypt_3544254952094837`。
- 固定函数名 `CQ_SM4_ENCRYPT` 通过 Doris `ALIAS FUNCTION` 指向当前版本的内部函数。

业务 SQL 始终保持：

```sql
SELECT CQ_SM4_ENCRYPT(column_name)
```

业务用户不需要知道内部函数名、jar 名或 Java class 名。

### 7.2 刷新密钥流程

每次刷新 SM4 密钥时，系统执行以下步骤：

1. 根据密钥种子计算密钥指纹。
2. 按旧加密逻辑生成实际 SM4 key：
   - 对密钥种子做 MD5。
   - 取 MD5 十六进制结果左 16 位。
   - 将这 16 位字符串作为 SM4 key。
3. 生成新的 UDF jar。
4. jar 内生成新的版本化 Java class/symbol。
5. 对每个目标 Doris 业务库执行：
   - 删除旧固定 alias/function。
   - 删除同版本内部函数，避免重复创建。
   - 创建新的内部 Java UDF 函数。
   - 创建固定函数名 alias，使 `CQ_SM4_ENCRYPT` 指向新的内部函数。
6. 使用固定函数名执行 SQL 验证。
7. 验证通过后，该库才标记为函数刷新成功。

### 7.3 Doris SQL 结构

内部版本函数示例：

```sql
CREATE FUNCTION CQ_SM4_ENCRYPT_3544254952094837(STRING)
RETURNS STRING
PROPERTIES (
  "file" = "http://.../cq-sm4-encrypt-3544254952094837-v3.jar",
  "symbol" = "CqSm4Encrypt_3544254952094837",
  "always_nullable" = "true",
  "type" = "JAVA_UDF"
)
```

固定函数名绑定示例：

```sql
CREATE ALIAS FUNCTION CQ_SM4_ENCRYPT(STRING)
WITH PARAMETER(x)
AS CQ_SM4_ENCRYPT_3544254952094837(x)
```

Doris 中 alias 的真实签名可能显示为 `text`，因此替换固定函数名时需要优先删除：

```sql
DROP FUNCTION IF EXISTS CQ_SM4_ENCRYPT(text)
```

同时兼容删除：

```sql
DROP FUNCTION IF EXISTS CQ_SM4_ENCRYPT(STRING)
DROP FUNCTION IF EXISTS CQ_SM4_ENCRYPT(VARCHAR)
```

### 7.4 创建后验证

系统不会仅凭 `CREATE FUNCTION` 成功就认为函数已生效。

系统会生成固定验证明文，并在后端用新密钥计算预期密文，然后在 Doris 中执行：

```sql
SELECT CQ_SM4_ENCRYPT('固定验证明文')
```

只有 Doris 返回值与后端预期密文完全一致时，才认为该库函数刷新成功。

如果返回值不一致，则说明固定函数名可能仍指向旧实现、旧 alias、旧 class 缓存或其他异常状态。此时：

- 当前库标记为失败。
- 整体刷新结果可能为失败或部分成功。
- 后续加密任务不应把该次函数刷新视为已生效。

### 7.5 不默认重启 Doris 集群

重启 Doris 集群是重操作，不作为默认换密钥流程。

默认策略：

- 不重启 FE。
- 不重启 BE。
- 通过内部版本函数和 alias 重新绑定规避同名 Java class 缓存。
- 通过固定函数名 SQL 验证确认真实生效。

只有在以下情况才考虑人工检查或重启 BE：

- 固定函数名验证失败。
- Doris 明确报 Java class 加载冲突。
- `SHOW CREATE FUNCTION` 显示 alias 未指向新版本函数。
- 运维确认当前 Doris 版本存在 Java UDF 热加载问题。

### 7.6 密钥与任务解耦

- 密钥创建、轮换、JAR 生成、函数部署和固定函数验证属于独立密钥管理操作。
- 保存 SM4 任务、执行一次、离线开发运行、上线调度和单表加密均不得隐式刷新密钥。
- 创建加密批次时，系统按“Doris 连接 + 目标数据库”绑定最近一次成功部署并验证的密钥版本。
- 批次必须永久记录实际绑定的密钥版本和指纹，密钥版本属于运行态审计信息，不进入 SM4 任务修订或生产内容快照。
- 批次执行任何目标表删除、创建或写入前，必须验证固定函数与批次绑定密钥一致；不一致时终止批次，不得自动刷新或改绑其他密钥。
- 需要轮换密钥时，由具备密钥管理权限的用户先独立完成部署和验证，后续新建批次自然绑定新的当前密钥。

### 7.7 离线开发来源追踪

- 离线开发节点提交 SM4 批次后，将批次 ID 写入节点运行结果。
- 后续成功、失败、超时或服务重启均保留该批次 ID，只追加状态和错误信息。
- 调度中心优先按批次 ID 关联离线工作流、上线版本和触发类型，不依赖批次提交人判断来源。
- 历史失败记录缺少结构化批次 ID 时，从错误文本中的 `SM4 batch <UUID>` 恢复关联。
- 离线调度触发的下层 SM4 批次必须显示为“离线开发 / 上线版本 / 调度触发”，不能误显示为手动任务。

### 7.8 按库选择与函数部署状态

- 密钥函数页面按当前 Doris 连接读取全部业务库，并以树形列表展示。
- 首次加载和切换连接时默认勾选全部业务库，用户可以全选、取消全选或逐库调整。
- “生成密钥并在选中库创建函数”只处理当前勾选的业务库，至少需要选择一个库。
- 每个业务库展示最近一次函数创建结果、密钥指纹和执行时间；失败原因通过行提示完整展示。
- 每库最近一次部署结果持久化到系统元数据库，页面刷新或服务重启后仍可追溯。
- 部署成功记录必须绑定实际密钥版本；部署失败的库不得自动使用本次新密钥。
- 创建 SM4 批次时，系统优先按“Doris 连接 + 目标数据库”解析最近一次成功部署的密钥版本。
- 当连接已有按库部署记录，但目标库没有成功记录或最近一次部署失败时，阻止任务提交并提示先重新创建和验证函数。
- 对尚未产生任何按库部署记录的历史连接，继续保留连接级密钥回退逻辑，确保旧任务平滑兼容。

## 8. 文件脱敏/解密

文件脱敏/解密用于处理已经离线导出的 JSON 或 CSV 文件。用户在前端上传文件后，选择需要解密的列，系统在后端复用现有 SM4 解密逻辑处理指定列，并返回 JSON 或 CSV 结果文件。

能力包括：
- 支持上传 `.json` 和 `.csv` 文件。
- CSV 默认第一行为表头，页面会自动识别列名。
- JSON 支持对象、对象数组，或包含 `rows` 数组的对象。
- 支持点击列名快速选择需要解密的字段，也支持手动输入列名，多个列用逗号分隔。
- 支持输出格式选择：保持原格式、JSON、CSV。
- 单个单元格解密失败时不终止整份文件处理，保留原值，并在结果摘要中展示失败数量和失败明细。
- 后端接口为 `POST /api/v1/doris-encryption/file-decrypt`，使用 `multipart/form-data` 上传文件和参数。

接口参数：
| 参数 | 说明 |
|---|---|
| `file` | 待处理 JSON 或 CSV 文件 |
| `columns` | 需要解密的列名，支持 JSON 数组字符串或逗号分隔文本 |
| `sm4_key` | 加密时使用的 SM4 密钥种子 |
| `output_format` | `preserve`、`json` 或 `csv` |

约束：
- 文件大小默认限制为 20MB。
- 该能力只处理上传文件内容，不直接修改 Doris 数据库。
- 解密逻辑复用系统已有 `sm4_decrypt_from_base64`，密钥种子必须与加密时一致。

## 9. 执行日志

执行日志提供按任务 ID 查询的全过程审计。

记录内容包括：

- 任务入队。
- 调度派发。
- Worker 接收。
- 任务开始运行。
- 单表开始。
- 建表、删表、插入等 Doris SQL。
- Doris 会话 ID。
- SQL 耗时。
- 影响行数。
- 停止请求和 SQL 中断尝试。
- 单表成功、失败或停止。
- 批次完成、失败或部分成功。

页面能力：

- 输入任务 ID 查询日志。
- 从任务调度列表一键跳转到日志页签。
- 清空当前日志查询结果。
