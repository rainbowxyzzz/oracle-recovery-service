# 前端 UI/UX 统一规范

## 1. 适用范围与目标

本规范适用于 `extracted-app/src/recovery_service/static/ui.html` 主工作台和独立的 `assistant.html`。本轮只统一表现层，不改变后端业务逻辑、API URL、请求字段、返回结构、数据库结构、权限语义或既有业务流程。

产品定位为现代、专业、克制的数据分析 / 数据中台后台。界面优先表达任务状态、影响范围、运行结果和可操作性，不使用营销式大面积装饰或夸张动画。

## 2. 页面扫描清单

主工作台包含以下入口和界面类型：

- 登录、当前用户、用户管理、API Key 管理
- 数据连接、数据导入 / 恢复、Doris CSV 导入
- Doris SQL 开发工作台、SQL 集合、查询导出任务
- 数据同步、数据变化触发器、离线开发、离线开发调度管理
- 批量授权中心、审批流自动授权、数据空间批量开通
- Doris SM4 加密中心、SM4 调度中心、SM4 密钥管理
- Doris SM3 映射脱敏、SM3 日志审计
- 接口编排中心（连接器、SQL API、流程画布、运行中心）
- 数据自动化流水线、数据血缘中心、数据库清理、帮助与架构中心
- 通用表单、查询区、工具栏、列表、表格、分页、详情、日志、Drawer / Modal / ContextMenu、画布和状态提示

独立 `assistant.html` 包含 Harness 规划、执行计划、四阶段进度、历史计划和审核确认弹窗。

## 3. 当前扫描发现的 UI 风险

- 共享页面已有较多局部 CSS，颜色、圆角、阴影、间距和控件高度存在历史差异。
- 顶部 Header、模块导航、页面工具栏和内容卡片缺少明确的层级节奏；窄屏下导航需要内部滚动，不能扩大页面级横向滚动。
- 查询表单在不同模块使用不同的 Grid / Flex 组合；本轮统一基础控件高度、标签层级和可换行规则，不重写各业务表单 DOM。
- 列表、表格、日志和状态标签的空态、悬停、选中和错误反馈颜色不完全统一。
- 画布节点、连线、端口、Tooltip、ContextMenu 使用 absolute 是其绘图模型所需，属于允许范围；不会把画布坐标模型强行改成普通文档流。
- 当前源码未发现 ECharts 引入、`echarts.init`、`setOption`、图表 `resize` 或 `ResizeObserver` 实例；因此本轮没有可实际修改的 ECharts 页面。后续新增图表必须遵守第 7 节容器与生命周期约束。

## 4. Design Tokens

### 4.1 色彩

| Token | 用途 | 值 |
| --- | --- | --- |
| `--background-page` | 页面背景 | `#f4f7fb` |
| `--background-card` | 卡片 / 面板 | `#ffffff` |
| `--background-subtle` | 工具栏 / 次级区 | `#f8fafc` |
| `--text-primary` | 主文字 | `#172b4d` |
| `--text-secondary` | 描述 / 标签 | `#63748a` |
| `--border-color` | 默认边框 | `#dbe4ee` |
| `--primary` | 主操作 / 当前态 | `#2167d5` |
| `--primary-soft` | 主色浅背景 | `#eef5ff` |
| `--success` / `--warning` / `--danger` | 状态语义 | `#16834a` / `#a15c00` / `#b42318` |

### 4.2 间距、圆角与层级

间距只优先使用 `4 / 8 / 12 / 16 / 24 / 32px`；控件高度默认 `36px`，紧凑控件使用 `30 / 32px`。默认圆角为 `8px`，输入控件为 `7px`，状态标签为 `999px`。阴影只用于悬浮或明确的工作台边界，避免重阴影。

层级按 `header → navigation → popover → modal → high-priority modal` 管理，分别使用 `30 / 40 / 50 / 80 / 100`；画布内部端口和节点层级只在自己的 stacking context 内使用低值。

## 5. 页面骨架与交互规范

业务页面优先使用 `PageHeader → Search/Form → ActionBar → ContentCard → Table/Chart/Log → Pagination` 的层级。`.toolbar` 承担页面标题或区块标题，`.actions` 承担操作集合，操作集合必须允许换行。

主操作使用 `.primary`，不可逆操作使用 `.danger`，取消 / 返回 / 刷新等使用默认次操作样式。所有按钮必须有 hover、focus-visible、disabled 状态；异步操作沿用现有 JS 状态，不新增重复请求或改变接口。

表格标题行、行高、边界、悬停和空态使用统一基础样式；业务表格需要横向滚动时只在 `.table-wrap` 或对应工作台内部滚动，不制造页面级横向溢出。文本默认左对齐，数值和时间字段由业务列规则决定，状态统一使用 `.state` / `.run-status` / `.badge` 语义色。

Modal / Drawer 必须限制在视口内，内容较多时内部滚动；关闭、确认和取消操作固定在清晰可达的操作区。现有画布和数据选择器的浮层互斥、消息生命周期和事件语义保持原实现，不在样式重构中改写。

## 6. 响应式验收基线

至少检查 `1366×768`、`1440×900`、`1600×900`、`1920×1080`，以及 100%、125%、150% 浏览器缩放。窄屏时导航、工作台、表格和画布可以使用各自内部滚动；页面整体不得出现无意义横向滚动、按钮遮挡、表单重叠或弹窗超出视口。

## 7. 图表与画布约束

图表必须放在有明确 `min-height` 或业务高度的容器中；初始化、容器变化、Tab / Drawer / Modal 展开后调用 resize；组件销毁时释放实例，且不得重复初始化。图表区域必须与搜索区和工具栏分离，Tooltip 不能覆盖关键操作。

画布节点和连线允许使用 absolute，因为坐标与 SVG 绘制是业务编辑模型的一部分；页面外层仍必须使用 Grid / Flex，节点尺寸变化时应由现有画布逻辑维护边界和滚动。

## 8. 本轮实现与边界

- 在主工作台增加统一 token、控件状态、卡片、工具栏、列表、表格、Modal、层级和响应式覆盖规则。
- 将独立 Harness 页面改为同一套 token 和交互状态视觉语言。
- 新增/修改仅限前端样式和规范文档；不修改后端、API、数据库、任务调度和业务 JS。
- 不删除现有入口、字段、按钮、数据区域或运行能力。
