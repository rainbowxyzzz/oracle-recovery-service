# 全链路数据自动化流水线 PRD

## 1. 背景与目标

系统已经具备 Oracle DMP 恢复、数据同步、离线开发、SM4/SM3、调度和日志能力，但各模块以任务 ID 独立存在，缺少贯穿“文件进入系统到形成标准安全资产”的统一批次、资产身份、处理蓝图和字段血缘。

本需求分四期连续建设：

1. 默认目录发现新 DMP 后自动创建统一批次，克隆已验证恢复模板，记录真实恢复目标，并派发数据同步。
2. 建立数据资产目录、Schema 指纹和蓝图匹配，按置信度自动选择或等待确认历史路径。
3. 改造离线开发，显式登记标准目标资产并采集字段级血缘。
4. 建立数据分类分级策略，经字段血缘反推源字段，生成受控 SM4 加密计划。

## 2. 核心对象

### 2.1 自动化流水线定义

保存监听目录、扫描间隔、稳定等待时间、文件匹配规则、恢复模板、同步任务、标准化生产版本、标准目标资产、分类策略、SM4 任务和自动执行闸门。凭据不得进入流水线配置，全部通过既有任务或连接引用获得。

### 2.2 数据批次

每个新文件组创建唯一 `data_batch_id`，记录来源文件、指纹、阶段状态、恢复/同步/标准化/加密运行 ID、真实目标库表、匹配置信度、错误、重试点和完整时间线。

### 2.3 数据资产

资产身份由 `连接 + Catalog/Schema + 表 + 业务层级` 构成，Schema 指纹由字段名、顺序、类型、可空性和主键/业务键规范化后计算。资产层级至少包括 `restored`、`raw`、`standard`、`secured`。

### 2.4 流水线蓝图

蓝图把源 Schema 指纹与恢复模板、同步任务、标准化生产版本、标准目标和安全策略绑定。蓝图版本不可变；运行中的批次冻结实际匹配版本。

### 2.5 字段级血缘

血缘边记录源资产/字段、目标资产/字段、转换类型、表达式摘要、工作流版本、节点和运行 ID。转换类型包括 `direct`、`rename`、`cast`、`expression`、`join`、`aggregate`、`constant`。

### 2.6 分类分级策略

按字段名规则、数据类型、业务标签和人工确认记录敏感类别、等级和保护动作。第一版支持 `public/internal/sensitive/highly_sensitive` 四级，以及 `none/mask/sm3/sm4/review` 动作。

## 3. 一期：文件发现、恢复与同步

- 扫描器通过已验证恢复模板中的 SSH 信息读取远端默认目录，只读取文件元数据，不读取 DMP 二进制内容。
- 支持单文件和 `%U` 分卷分组；同一文件路径、大小和修改时间形成发现幂等键。
- 文件必须在配置的稳定等待时间内大小和修改时间不变，才能进入 `ready`。
- 新批次克隆恢复模板的加密凭据和执行快照，只替换 `manual_dumpfile`、来源目录、流水线/批次关联字段；禁止修改原模板。
- 恢复任务只有进入 `succeeded` 或 `succeeded_with_warnings` 且具有明确目标 Schema，批次才能进入同步阶段。
- 恢复真实目标连接、Schema 和对象清单写入批次产物；不得用预期名称替代实际运行结果。
- 自动恢复生成新 Oracle 用户后，系统必须使用恢复任务冻结的 Oracle 目标连接快照和已加密保存的生成用户口令，由数据同步 Worker 直连该用户并通过 Stream Load 写入 Doris；不得依赖 Doris JDBC Catalog 枚举新用户，也不得把明文口令写入流水线、批次、运行结果或日志。原有手工 Doris Catalog 同步行为保持不变。
- 同步阶段引用既有数据同步任务修订或离线生产快照。目标源对象必须与恢复产物一致，不一致时阻断而不是猜测。
- 每个阶段使用 `pipeline_id + batch_id + stage + blueprint_version` 作为幂等键；重复扫描、重复消息和服务重启不得重复创建运行。

## 4. 二期：资产、指纹和路径匹配

- 恢复成功和同步成功后登记或更新资产及字段结构。
- Schema 指纹完全一致且来源规则一致为高置信度；字段兼容但有新增/类型扩大为中置信度；缺字段、类型收窄或语义冲突为低置信度。
- 高置信度且蓝图允许自动执行时可自动选择路径；中置信度生成推荐并等待确认；低置信度必须阻断。
- 仅表结构相同不等于业务含义相同。蓝图必须同时匹配来源规则或业务主题，禁止跨来源无条件复用。
- 管理员确认一次中置信度匹配后可创建新蓝图版本，后续同类数据使用新版本。

## 5. 三期：标准目标与字段血缘

- 离线开发工作流及生产版本增加 `business_domain`、`standard_target`、`input_assets` 和 `lineage_contract` 业务元数据，保持旧流程字段兼容。
- 生产版本提交时冻结标准目标和血缘合同；后续修改开发版不改变已上线批次。
- 数据同步字段映射、Doris SQL 显式别名及 SM4/SM3 字段映射自动生成可证明的血缘边。
- 无法可靠解析的复杂 SQL 只登记表级血缘并标记 `review_required=true`，不得伪造字段级直接映射。
- 血缘查询支持批次向下追踪、标准字段向上追踪及影响分析。

## 6. 四期：分类分级与血缘反推加密

- 标准资产字段先应用分类分级策略，结果带策略版本、证据和置信度。
- `direct/rename/cast` 血缘允许把 SM4 保护建议自动传播到源字段；`expression/join/aggregate` 只生成待确认建议。
- 主键、业务键、Join 键、水位字段和分区字段默认进入人工确认，不自动加密。
- 已 SM3、已 SM4 或不可逆脱敏字段不得重复加密。
- 反推结果只生成加密计划草案；只有策略允许自动执行、源库 `encrypt_enabled=true`、SM4 函数与密钥预检成功且无在途冲突时才能创建批次。
- 加密计划永久记录实际密钥版本、指纹、来源血缘边和策略版本，但不保存密钥种子。
- SM4 批次成功后登记 `secured` 资产，并记录原始表到安全表的表级与字段级血缘；加密字段标记为 `expression/SM4_ENCRYPT`，未加密字段标记为 `direct`，血缘证据只保存密钥指纹和批次 ID，不保存密钥种子。

## 7. 状态机

断点继续必须创建新的阶段运行记录：恢复失败后克隆新的 `RecoveryTask`，同步失败后创建新的组件运行，标准化失败后创建新的工作流运行；不得复用已失败的运行 ID，否则会立即重复读取旧失败结果。

Oracle 自动恢复创建新 Schema 后，系统必须把本次恢复用户的临时 Oracle 直连上下文注入新的同步运行，并强制使用 Stream Load；连接快照或加密口令缺失时不得继续写入原始层。普通非自动化同步继续使用原 Catalog，不改变既有行为。

主状态依次为：

`discovered → stabilizing → restore_queued → restoring → restored → asset_registered → sync_queued → syncing → raw_ready → path_matching → awaiting_confirmation/standardize_queued → standardizing → standard_ready → lineage_ready → classified → encryption_planned → encrypting → completed`

失败状态为 `blocked`、`failed`、`partial`、`cancelled`。失败必须保留 `resume_from_stage`，重跑从未完成阶段继续，不得重复执行已成功阶段。

## 8. 事务与并发

- 系统元数据库保存阶段状态、运行绑定和事件，使用条件更新抢占阶段。
- Oracle、Doris 和外部系统不属于同一数据库事务；采用 Saga 补偿、幂等键和可核对产物保证最终一致性。
- 批次状态提交与下游任务登记必须处于同一系统库事务；消息派发失败时任务保持可重派发状态。
- 服务启动后扫描非终态批次，依据实际下游任务状态恢复推进。
- 同一文件幂等键、同一批次阶段和同一目标资产不得并发重复执行。

## 9. 页面能力

- 新增“数据自动化流水线”模块。
- 流水线列表显示监听开关、目录、间隔、最近/下次扫描、蓝图和在途批次。
- 批次时间线展示文件、恢复目标、同步目标、标准目标、血缘、分类和加密结果。
- 资产视图展示 Schema 指纹、字段、分级和上下游。
- 匹配中心展示候选蓝图、置信度、差异和确认入口。
- 血缘视图支持向上/向下追踪，明确区分字段级已证明、表级推断和待确认关系。

### 9.1 独立数据血缘中心

数据血缘不得只作为“数据自动化流水线”资产表中的隐含能力。左侧一级导航新增独立“数据血缘中心”，面向数据管理员、开发人员和审计人员提供只读的统一查询入口，并继续复用现有资产与血缘记录，不迁移、不复制和不改写历史数据。

- 首页提供资产数、血缘边数、字段级关系数、待确认关系数和 SM4 传播关系数等摘要，支持按资产关键字、业务层级、数据批次筛选。
- 资产关键字至少可以匹配引擎、Catalog、数据库、表名、业务域、字段名和 Schema 指纹；筛选为空时展示最近更新资产及其关系。
- 用户选择根资产后，可切换“查看上游”或“查看下游”，并选择 1 至 20 层追踪深度；追踪结果必须明确标识根节点、资产层级和方向。
- 主视区按 `restored → raw → standard → secured` 分层展示资产图谱；图谱节点显示库表、引擎和层级，不要求用户识别 UUID。
- 血缘关系区分表级关系和字段级关系，并展示 `direct/rename/cast/expression/join/aggregate/constant` 转换类型、置信度、是否需要人工确认、工作流版本、节点和批次证据。
- `SM4_ENCRYPT` 或其他加密表达式必须显著标识，使管理员可以从标准敏感字段追溯至原始字段及安全表；页面不得展示密钥种子、凭据或未脱敏请求体。
- 采用三级信息结构：一级为独立血缘中心，二级为选中资产的详情与上下游关系，三级为字段合同、关系证据和完整表达式详情窗口；不得把长 JSON 和字段列表挤在主表中。
- 资产和关系均可点击；选中资产后保留当前筛选条件，刷新和切换方向不得把用户带回自动化流水线页面。
- 第一版为只读能力，不提供删除资产、删除血缘、修改表达式或直接执行加密的入口；写操作仍由原流水线、离线开发和 SM4 模块负责。
- “数据自动化流水线”原有流水线创建、监听开关、批次继续、阶段日志和资产列表保持兼容；资产列表可增加“查看血缘”跳转，但不得改变原保存和运行语义。

验收要求：使用已完成四层自动化批次验证资产检索、批次过滤、上游/下游切换、追踪深度、表级/字段级关系、两条 SM4 字段传播关系、二三级详情窗口和页面刷新；同时在最大化、左右半屏和还原窗口检查无横向页面溢出、关键操作可见且浏览器控制台无错误。

### 9.2 OpenMetadata 模型与 OpenLineage 事件兼容扩展

为支持后续 AI 数据问答、影响分析和自动化治理，血缘中心增加标准化交换边界，但不引入独立 OpenMetadata 服务，不改变现有四层资产、血缘查询和任务运行语义。

- 内部 `DataAsset` 继续作为唯一事实来源，并提供 OpenMetadata 风格的实体投影：`entityType`、`fullyQualifiedName`、`serviceName`、`databaseSchema`、`tableName`、`columns`、`tags` 和 `updatedAt`。实体名称使用稳定的 `engine.catalog.database.table.layer` 规则，不能因页面显示名变化而变化。
- 内部 `DataLineageEdge` 继续作为唯一关系事实来源，并提供 OpenMetadata 风格的 `fromEntity`、`toEntity`、`lineageDetails` 投影；字段关系放入 `lineageDetails.fields`，表级推断保留 `reviewRequired=true`，不能把无法证明的复杂 SQL 伪造成字段直连。
- 新增轻量 OpenLineage RunEvent 接收能力，支持 `START`、`RUNNING`、`COMPLETE`、`FAIL`、`ABORT` 和 `OTHER` 状态；事件保存 `eventType`、`eventTime`、`producer`、`schemaURL`、`run`、`job`、`inputs`、`outputs` 和受控 facets，按事件幂等键去重。
- OpenLineage dataset 的 `namespace + name` 映射到内部资产；未匹配的输入/输出只保留事件，不自动创建缺少连接、数据库或 Schema 合同的业务资产。匹配成功后生成表级关系；标准 `columnLineage` facet 仅为可解析的输入/输出字段生成字段级关系。
- 事件状态只记录运行证据，不替代批次或工作流状态。事件接收失败不得阻断既有任务；事件接口和查询接口沿用 `dataPlatform:read/design` 权限，原始事件不得保存凭据、请求体、密钥种子或 SQL 中的敏感值。
- 支持按 `job.namespace`、`job.name`、`run.runId` 和时间范围查询事件，并在血缘关系上标识来源为 `native` 或 `openlineage`。AI 使用方优先读取 OpenMetadata 风格实体投影和已确认字段关系，不直接读取原始事件 JSON。
- 第一版只提供标准事件接收、幂等审计和只读投影，不提供事件反向修改资产、删除血缘、自动发布 OpenMetadata 服务或将事件转发到外部消息系统的能力；未来可在不改变内部事实表的前提下增加 Kafka/HTTP exporter、OpenMetadata API exporter 和 AI 检索索引。

验收要求：同一 OpenLineage 事件重复提交只产生一条事件记录和一组血缘边；含 `columnLineage` facet 的事件生成字段关系；不含 facet 的事件只生成表级关系；未知 dataset 不创建虚假资产；事件查询与 OpenMetadata 风格导出不泄露敏感信息；既有四层血缘 API、页面、任务运行和 SM4 回归保持通过。

### 9.3 数据库分组统计与库业务层级配置

血缘中心的统计和筛选不能只停留在资产或表级。系统增加数据库维度的只读聚合，并提供管理员可维护的库业务层级配置。

- 数据库分组键为 `engine + connection + catalog + database`；同名数据库在不同连接或 Catalog 下必须分开统计，不能合并为一个展示组。
- 每个数据库组至少展示资产数、血缘关系数、字段级关系数、待确认关系数、SM4 传播关系数，以及当前库业务层级和最近更新时间。
- `数据层级` 继续使用现有 `restored/raw/standard/secured`，只描述单个资产在四层链路中的位置；不得用库业务层级替代或回写该字段。
- `库业务层级`是人工配置字符串，支持 `ODS`、`DWD`、`DWS`、`ADS`、业务域名称或用户系统中的其他稳定标签；保存前后必须真实回读，刷新页面不得丢失。未配置时显示“未配置”，系统不得根据库名或表名自动猜测。
- 配置实体只保存库定位信息、业务层级、备注、修改人和修改时间，不保存凭据；配置修改只影响统计、筛选和展示，不改写资产、血缘边、批次、任务、调度或 OpenLineage 事件。
- 血缘中心支持按数据库组筛选；筛选后资产图谱、关系表、摘要指标和 OpenMetadata 风格投影必须使用同一筛选范围。跨库关系在来源库和目标库的组统计中各计一次，并在关系详情中保留真实两端。
- 库业务层级配置入口放在数据血缘中心和数据自动化任务工作区的“数据库治理”区域；页面采用保存/刷新/回读闭环，不能通过删除资产或重跑任务完成配置。

验收要求：至少准备两个同名不同连接或 Catalog 的数据库，统计必须分成两个组；配置一个库的业务层级后刷新仍保持，另一个库不受影响；按库筛选时资产、关系和指标一致；现有四层数据层级、OpenLineage 事件、任务运行和 SM4 关系回归保持通过。

## 10. 兼容性边界

- 旧恢复任务、同步任务、离线流程、SM4/SM3 任务、调度和运行记录保持不变。
- 自动化流水线只引用或克隆既有快照，不回写原定义。
- 默认关闭自动监听和自动加密；升级后不会自行扫描生产目录或处理历史文件。
- 第一版只支持 Oracle Data Pump 自动入口；传统 exp、加密 DMP、Transportable Tablespaces 和无法建立恢复合同的文件进入阻断状态。
- 删除流水线不删除历史批次、资产、血缘、业务表或既有任务。

## 11. 验收

1. 隔离目录新增 Data Pump DMP 后只创建一个批次，文件未稳定时不恢复。
2. 恢复成功后记录实际目标 Schema，并自动创建一次同步运行。
3. 相同 Schema 指纹再次进入时匹配同一蓝图；不兼容结构进入确认或阻断。
4. 标准化运行绑定冻结生产版本和标准目标。
5. 能从标准字段追溯至 Doris 原始字段及 Oracle 恢复字段。
6. 直接血缘的敏感字段能生成源表 SM4 草案；复杂表达式不会自动执行。
7. 任一阶段失败后可从断点恢复，已成功恢复/同步不会重复执行。
8. 测试前后既有任务、密钥、调度和离线版本数量及内容不变。
