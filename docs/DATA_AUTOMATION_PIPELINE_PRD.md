# 全链路数据自动化流水线 PRD

## 1. 背景与目标

系统已经具备 Oracle DMP 恢复、数据同步、离线开发、SM4/SM3、调度和日志能力，但各模块以任务 ID 独立存在，缺少贯穿“文件进入系统到形成标准安全资产”的统一批次、资产身份、处理蓝图和字段血缘。

本需求分四期连续建设：

1. 默认目录发现新 DMP 后自动创建统一批次，克隆已验证恢复模板，记录真实恢复目标，并派发数据同步。
2. 建立数据资产目录、Schema 指纹和蓝图匹配，按置信度自动选择或等待确认历史路径。
3. 改造离线开发，显式登记标准目标资产并采集字段级血缘。
4. 建立数据分类分级策略，经字段血缘反推源字段，生成受控 SM4 加密计划。

## 2. 核心对象

### 2.1 自动化流水线定义

保存监听目录、扫描间隔、稳定等待时间、文件匹配规则、恢复模板、同步任务、标准化生产版本、标准目标资产、分类策略、SM4 任务和自动执行闸门。凭据不得进入流水线配置，全部通过既有任务或连接引用获得。

### 2.2 数据批次

每个新文件组创建唯一 `data_batch_id`，记录来源文件、指纹、阶段状态、恢复/同步/标准化/加密运行 ID、真实目标库表、匹配置信度、错误、重试点和完整时间线。

### 2.3 数据资产

资产身份由 `连接 + Catalog/Schema + 表 + 业务层级` 构成，Schema 指纹由字段名、顺序、类型、可空性和主键/业务键规范化后计算。资产层级至少包括 `restored`、`raw`、`standard`、`secured`。

### 2.4 流水线蓝图

蓝图把源 Schema 指纹与恢复模板、同步任务、标准化生产版本、标准目标和安全策略绑定。蓝图版本不可变；运行中的批次冻结实际匹配版本。

### 2.5 字段级血缘

血缘边记录源资产/字段、目标资产/字段、转换类型、表达式摘要、工作流版本、节点和运行 ID。转换类型包括 `direct`、`rename`、`cast`、`expression`、`join`、`aggregate`、`constant`。

### 2.6 分类分级策略

按字段名规则、数据类型、业务标签和人工确认记录敏感类别、等级和保护动作。第一版支持 `public/internal/sensitive/highly_sensitive` 四级，以及 `none/mask/sm3/sm4/review` 动作。

## 3. 一期：文件发现、恢复与同步

- 扫描器通过已验证恢复模板中的 SSH 信息读取远端默认目录，只读取文件元数据，不读取 DMP 二进制内容。
- 支持单文件和 `%U` 分卷分组；同一文件路径、大小和修改时间形成发现幂等键。
- 文件必须在配置的稳定等待时间内大小和修改时间不变，才能进入 `ready`。
- 新批次克隆恢复模板的加密凭据和执行快照，只替换 `manual_dumpfile`、来源目录、流水线/批次关联字段；禁止修改原模板。
- 恢复任务只有进入 `succeeded` 或 `succeeded_with_warnings` 且具有明确目标 Schema，批次才能进入同步阶段。
- 恢复真实目标连接、Schema 和对象清单写入批次产物；不得用预期名称替代实际运行结果。
- 自动恢复生成新 Oracle 用户后，系统必须使用恢复任务冻结的 Oracle 目标连接快照和已加密保存的生成用户口令，由数据同步 Worker 直连该用户并通过 Stream Load 写入 Doris；不得依赖 Doris JDBC Catalog 枚举新用户，也不得把明文口令写入流水线、批次、运行结果或日志。原有手工 Doris Catalog 同步行为保持不变。
- 同步阶段引用既有数据同步任务修订或离线生产快照。目标源对象必须与恢复产物一致，不一致时阻断而不是猜测。
- 每个阶段使用 `pipeline_id + batch_id + stage + blueprint_version` 作为幂等键；重复扫描、重复消息和服务重启不得重复创建运行。

## 4. 二期：资产、指纹和路径匹配

- 恢复成功和同步成功后登记或更新资产及字段结构。
- Schema 指纹完全一致且来源规则一致为高置信度；字段兼容但有新增/类型扩大为中置信度；缺字段、类型收窄或语义冲突为低置信度。
- 高置信度且蓝图允许自动执行时可自动选择路径；中置信度生成推荐并等待确认；低置信度必须阻断。
- 仅表结构相同不等于业务含义相同。蓝图必须同时匹配来源规则或业务主题，禁止跨来源无条件复用。
- 管理员确认一次中置信度匹配后可创建新蓝图版本，后续同类数据使用新版本。

## 5. 三期：标准目标与字段血缘

- 离线开发工作流及生产版本增加 `business_domain`、`standard_target`、`input_assets` 和 `lineage_contract` 业务元数据，保持旧流程字段兼容。
- 生产版本提交时冻结标准目标和血缘合同；后续修改开发版不改变已上线批次。
- 数据同步字段映射、Doris SQL 显式别名及 SM4/SM3 字段映射自动生成可证明的血缘边。
- 无法可靠解析的复杂 SQL 只登记表级血缘并标记 `review_required=true`，不得伪造字段级直接映射。
- 血缘查询支持批次向下追踪、标准字段向上追踪及影响分析。

## 6. 四期：分类分级与血缘反推加密

- 标准资产字段先应用分类分级策略，结果带策略版本、证据和置信度。
- `direct/rename/cast` 血缘允许把 SM4 保护建议自动传播到源字段；`expression/join/aggregate` 只生成待确认建议。
- 主键、业务键、Join 键、水位字段和分区字段默认进入人工确认，不自动加密。
- 已 SM3、已 SM4 或不可逆脱敏字段不得重复加密。
- 反推结果只生成加密计划草案；只有策略允许自动执行、源库 `encrypt_enabled=true`、SM4 函数与密钥预检成功且无在途冲突时才能创建批次。
- 加密计划永久记录实际密钥版本、指纹、来源血缘边和策略版本，但不保存密钥种子。
- SM4 批次成功后登记 `secured` 资产，并记录原始表到安全表的表级与字段级血缘；加密字段标记为 `expression/SM4_ENCRYPT`，未加密字段标记为 `direct`，血缘证据只保存密钥指纹和批次 ID，不保存密钥种子。

### 6.1 安全访问层（2026-09-07）

- 明文源表、标准表和既有 ETL 物理对象保持不变；系统不得用自动重命名或原表覆盖代替 Doris 下游普通账号的数据保护。
- SM4 任务可保存不可变的“加密覆盖合同”：标准资产/字段、可证明的源资产/字段、预期安全对象/字段和 Doris 下游账号访问别名。合同随 SM4 任务修订和生产工作流版本冻结。
- 首次反向加密合同只能在已上线 SQL 集合或生产工作流成功后生成和执行；合同启用后的后续批次则依据该冻结合同在 DWD 工作流之前加密 ODS。标准字段必须已被分级为 `sm4`，ODS 源字段必须通过唯一的 `direct`、`rename` 或 `cast` 血缘边反向定位，且合同、连接、数据库、字段、Schema 指纹和 SM4 任务快照完全匹配；`expression`、`join`、`aggregate`、多路径或未确认血缘一律阻断自动执行。
- 加密成功后创建/刷新独立 `secured` 表，并在受控访问数据库创建安全视图或逻辑别名。当前平台登录者均为超级管理员，保留原始明文治理能力；安全限制专指平台外部的 Doris 下游业务账号或应用账号，此类账号仅允许访问安全对象。ETL 服务账号按最小权限读取明文对象。安全对象缺失、加密失败、Schema 变化或映射过期时，Doris 下游账号访问必须失败，禁止回退到明文。
- 受限 SQL 仅允许读取语句，并使用 Doris SQL AST 解析表引用后替换为已激活的安全视图，禁止正则或字符串替换。对加密字段参与 Join、过滤、分组、排序、聚合或函数计算的语句必须阻断，除非后续另行定义可证明的密文计算合同。
- 当前平台不设置普通 SQL 开发用户，平台登录者均按超级管理员治理场景使用。直接连接 Doris 的下游普通账号不进入当前平台，其授权不自动推断或批量撤销；管理员须显式撤销这些账号的原始表授权、仅授予 `access` 库视图，以避免数据库直连访问明文。
- 安全映射、解析结果、工作流版本、SM4 修订、批次 ID、密钥指纹、OpenMetadata 同步状态均需审计；不得保存密钥种子、明文查询参数或明文数据样本。

### 6.2 业务数据流编排与运行台账（2026-09-08）

数据自动化流水线是业务数据流的唯一事实来源；本轮不新增第二套任务定义或复制既有恢复、同步、SQL、SM4 与调度执行器。新增的“数据流编排与运行台账”以每条流水线为单位聚合其冻结引用、批次、阶段事件、资产、字段血缘、SM4 覆盖合同和安全访问映射。

- 一条业务流必须展示并区分两类路径。首次建模路径为 `Oracle 自动还原 → 全表同步至受限 ODS 明文落地区 → DWD SQL 标准化 → 字段血缘与分级 → 反向生成 ODS SM4 合同 → 创建 ODS 安全表与访问别名`，用于取得可证明的标准字段、字段血缘和加密依据。后续受保护路径为 `Oracle 自动还原 → 全表同步至受限 ODS 明文落地区 → 校验冻结合同与 Schema → ODS SM4 → 激活安全别名 → DWD SQL（protected_etl 安全数据加工）→ 调度/OpenMetadata`，必须在 DWD SQL 之前完成加密和安全路由。
- Oracle 只承担自动还原和同步来源职责，不新增 Oracle SM4 自定义函数，也不改写 Oracle 源表。反向加密的物理源头固定为 Doris ODS 层；DWD 层的敏感字段分类和字段血缘只作为反向定位 ODS 表、字段及加密策略的证据。
- 每个自动化恢复批次必须基于实际恢复 Schema 重新发现全部 Oracle 表并生成本批次同步映射，不得沿用恢复模板中的旧表清单或人工勾选子集；动态映射只写入批次运行快照和资产血缘，不得反向覆盖可复用的数据同步组件模板。普通手工数据同步仍保留按表选择能力。
- ODS 明文落地区允许平台超级管理员以及恢复、同步、加密执行器和受控平台服务账号按职责访问；平台外部的 Doris 下游普通账号不得直接读取。SM4 成功后创建/刷新独立 ODS 安全表，并由安全视图或逻辑别名提供访问；安全对象、映射或合同不可用时必须阻断下游普通账号，禁止其回退到 ODS 明文表。
- 安全编排只能在指定标准资产的安全访问计划 `ready=true` 后启用。启用时冻结 `mode=ods_protected`、标准资产、生产工作流版本、SM4 任务及修订、ODS 源资产及 Schema 指纹、字段覆盖合同和合同哈希；快照只保存版本与资产标识，不得保存凭据、密钥种子或明文数据。每个新批次发现时复制该快照，流水线后续修改不得改变在途批次语义。
- 启用前或结构变化后的学习批次保持“先 DWD 建模、后反向 ODS 加密”的一次性顺序。启用后的新批次在 ODS 同步成功后先核验批次 ODS 资产是否与冻结快照完全匹配；通过后自动提交 ODS SM4，激活安全别名，再以 `security_access_mode=protected_etl` 安全数据加工模式启动冻结的 DWD 工作流。该模式允许冻结工作流执行现有的查询、`INSERT ... SELECT` 和 `CREATE TABLE ... AS SELECT` 数据加工语句，但只改写读取来源，不改写 DWD 写入目标；冻结合同中的 ODS 来源必须解析到已激活安全别名。任何合同、Schema、字段血缘、SM4 修订或安全路由漂移都必须把批次置为阻断状态，不能继续 DWD SQL，也不能使用明文兜底。
- 若管理员在当前 `standard_ready` 学习批次启用，批次直接进入 `encryption_ready`；若该学习批次已结束，则创建只含 ODS 加密和安全路由阶段、引用原批次产物的补偿批次，不重跑恢复、同步或 SQL。补偿批次完成后只负责建立首份安全合同，不重复执行 DWD 工作流。
- 受保护批次的 DWD SQL 必须由运行上下文强制进入 `protected_etl` 安全数据加工模式，该上下文优先于工作流节点保存的 `trusted` 配置。SQL AST 只把冻结合同中的逻辑 ODS 读取来源解析到已激活安全别名，保留 DWD 写入目标；首版覆盖现有生产任务实际使用的查询、`INSERT ... SELECT` 和 `CREATE TABLE ... AS SELECT`，其他语句保持原有可信工作流语义但不得被误改写。未激活、过期或歧义映射一律报错，禁止安全数据加工回退到合同中的 ODS 明文来源。
- 台账可查询每条业务流的绑定对象、最近批次、各阶段状态、资格检查、加密映射和审计事件；页面提供“查看血缘”“核验安全资格”“生成反向加密任务”“一键进行加密”“一键切换安全路由”和“启用安全编排”。生成动作只创建受控的 `encryption_ready` 批次；提交动作创建真实 SM4 批次；安全路由动作只允许在 SM4 成功后激活安全别名。所有动作继续走原有权限、确认、队列、幂等和失败恢复机制。

验收要求：创建含有效 SM4 覆盖合同的隔离流水线后，台账可准确聚合其状态和映射；资格核验失败不改变流水线配置；启用成功后冻结安全编排快照并记录审计事件；学习批次按“标准化后加密”完成首次建模，后续批次按“ODS 加密后 protected_etl 安全数据加工 DWD SQL”执行；`INSERT ... SELECT` 和 `CREATE TABLE ... AS SELECT` 必须保留 DWD 目标并把合同内 ODS 来源替换为安全别名；批次快照不受流水线后续编辑影响；无合同、复杂血缘、Schema 漂移、SM4 修订漂移或未激活映射均不得继续；最终资产、字段血缘、加密记录、安全路由与批次状态可进入 OpenMetadata 出站队列。

### 6.3 阶段可靠派发与幂等执行（2026-09-09）

- 数据自动化的 Oracle 恢复、数据同步、DWD 标准化和 ODS SM4 阶段统一使用系统库阶段派发表。业务批次状态、对应下游执行实体和阶段派发记录必须在同一事务中提交；禁止先向消息队列派发、再回写批次关联运行编号。
- 阶段派发记录以“业务批次 + 阶段 + 目标执行实体”形成唯一幂等键，记录目标类型、目标编号、派发状态、尝试次数、消息任务编号、最近错误和时间。正常断点重试创建新的目标执行实体和新的派发记录，历史记录不得覆盖。
- 派发语义固定为“至少一次投递 + 幂等执行”。派发成功但状态回写前进程退出时，系统允许使用同一派发编号再次投递；恢复、同步、工作流和 SM4 执行器必须使用原子状态抢占，只有一个执行器可以把目标从待执行改为运行中，其余重复消息只记录并退出，不得重复写业务数据。
- 阶段派发失败不得把业务批次直接标记为业务失败。派发记录保留为待派发并按有限退避自动重试；服务启动或定时推进时扫描待派发和超时派发中的记录。下游执行实体明确失败后，业务批次才按原有断点规则进入失败状态。
- 台账必须返回每个批次的阶段派发记录，并展示待派发、已派发、运行中、成功和失败状态；不得把“已登记待派发”误报成“任务正在运行”。
- 本轮只强化数据自动化触发的四类阶段，不改变人工运行、定时运行、任务业务顺序、权限、SQL、SM4 算法或外部系统事务边界。

验收要求：模拟事务提交后消息发送失败，阶段派发记录和执行实体仍可被定时器补发；模拟发送成功但派发状态未回写，同一派发编号重复投递时只允许一个执行器实际运行；并发调用批次推进不得为同一目标生成重复派发记录；正常失败重试必须生成新的目标实体和历史派发记录；台账可查询完整派发状态；既有恢复、同步、标准化、加密、安全路由和断点续跑回归保持通过。

## 7. 状态机

断点继续必须创建新的阶段运行记录：恢复失败后克隆新的 `RecoveryTask`，同步失败后创建新的组件运行，标准化失败后创建新的工作流运行；不得复用已失败的运行 ID，否则会立即重复读取旧失败结果。

Oracle 自动恢复创建新 Schema 后，系统必须把本次恢复用户的临时 Oracle 直连上下文注入新的同步运行，并强制使用 Stream Load；连接快照或加密口令缺失时不得继续写入原始层。普通非自动化同步继续使用原 Catalog，不改变既有行为。

主状态分为：

- 首次建模/补偿路径：`discovered → stabilizing → restore_queued → restoring → restored → asset_registered → sync_queued → syncing → raw_ready → standardize_queued → standardizing → standard_ready → lineage_ready/classified → encryption_ready → encrypting → completed`。
- 后续受保护路径：`discovered → stabilizing → restore_queued → restoring → restored → asset_registered → sync_queued → syncing → raw_ready → security_contract_validating → encryption_ready → encrypting → security_access_active → standardize_queued(protected_etl) → standardizing → standard_ready → completed`。

失败状态为 `blocked`、`failed`、`partial`、`cancelled`。失败必须保留 `resume_from_stage`，重跑从未完成阶段继续，不得重复执行已成功阶段。

## 8. 事务与并发

- 系统元数据库保存阶段状态、运行绑定和事件，使用条件更新抢占阶段。
- Oracle、Doris 和外部系统不属于同一数据库事务；采用 Saga 补偿、幂等键和可核对产物保证最终一致性。
- 批次状态提交与下游任务登记必须处于同一系统库事务；消息派发失败时任务保持可重派发状态。
- 服务启动后扫描非终态批次，依据实际下游任务状态恢复推进。
- 同一文件幂等键、同一批次阶段和同一目标资产不得并发重复执行。

## 9. 页面能力

- 新增“数据自动化流水线”模块。
- 流水线列表显示监听开关、目录、间隔、最近/下次扫描、蓝图和在途批次。
- 批次时间线展示文件、恢复目标、同步目标、标准目标、血缘、分类和加密结果。
- 资产视图展示 Schema 指纹、字段、分级和上下游。
- 匹配中心展示候选蓝图、置信度、差异和确认入口。
- 血缘视图支持向上/向下追踪，明确区分字段级已证明、表级推断和待确认关系。

### 9.1 独立数据血缘中心（历史版本，已废弃）

本节描述的自研资产目录、上下游图谱、数据库统计和库业务层级编辑页面仅作为历史版本记录，后续不再作为正式产品入口。正式入口以 9.4 的 OpenMetadata 原生 UI 集成为准。

数据血缘不得只作为“数据自动化流水线”资产表中的隐含能力。左侧一级导航新增独立“数据血缘中心”，面向数据管理员、开发人员和审计人员提供只读的统一查询入口，并继续复用现有资产与血缘记录，不迁移、不复制和不改写历史数据。

- 首页提供资产数、血缘边数、字段级关系数、待确认关系数和 SM4 传播关系数等摘要，支持按资产关键字、业务层级、数据批次筛选。
- 资产关键字至少可以匹配引擎、Catalog、数据库、表名、业务域、字段名和 Schema 指纹；筛选为空时展示最近更新资产及其关系。
- 用户选择根资产后，可切换“查看上游”或“查看下游”，并选择 1 至 20 层追踪深度；追踪结果必须明确标识根节点、资产层级和方向。
- 主视区按 `restored → raw → standard → secured` 分层展示资产图谱；图谱节点显示库表、引擎和层级，不要求用户识别 UUID。
- 血缘关系区分表级关系和字段级关系，并展示 `direct/rename/cast/expression/join/aggregate/constant` 转换类型、置信度、是否需要人工确认、工作流版本、节点和批次证据。
- `SM4_ENCRYPT` 或其他加密表达式必须显著标识，使管理员可以从标准敏感字段追溯至原始字段及安全表；页面不得展示密钥种子、凭据或未脱敏请求体。
- 采用三级信息结构：一级为独立血缘中心，二级为选中资产的详情与上下游关系，三级为字段合同、关系证据和完整表达式详情窗口；不得把长 JSON 和字段列表挤在主表中。
- 资产和关系均可点击；选中资产后保留当前筛选条件，刷新和切换方向不得把用户带回自动化流水线页面。
- 第一版为只读能力，不提供删除资产、删除血缘、修改表达式或直接执行加密的入口；写操作仍由原流水线、离线开发和 SM4 模块负责。
- “数据自动化流水线”原有流水线创建、监听开关、批次继续、阶段日志和资产列表保持兼容；资产列表可增加“查看血缘”跳转，但不得改变原保存和运行语义。

验收要求：使用已完成四层自动化批次验证资产检索、批次过滤、上游/下游切换、追踪深度、表级/字段级关系、两条 SM4 字段传播关系、二三级详情窗口和页面刷新；同时在最大化、左右半屏和还原窗口检查无横向页面溢出、关键操作可见且浏览器控制台无错误。

### 9.2 OpenMetadata 模型与 OpenLineage 事件兼容扩展

为支持后续 AI 数据问答、影响分析和自动化治理，血缘中心增加标准化交换边界，但不引入独立 OpenMetadata 服务，不改变现有四层资产、血缘查询和任务运行语义。

- 内部 `DataAsset` 继续作为唯一事实来源，并提供 OpenMetadata 风格的实体投影：`entityType`、`fullyQualifiedName`、`serviceName`、`databaseSchema`、`tableName`、`columns`、`tags` 和 `updatedAt`。实体名称使用稳定的 `engine.catalog.database.table.layer` 规则，不能因页面显示名变化而变化。
- 内部 `DataLineageEdge` 继续作为唯一关系事实来源，并提供 OpenMetadata 风格的 `fromEntity`、`toEntity`、`lineageDetails` 投影；字段关系放入 `lineageDetails.fields`，表级推断保留 `reviewRequired=true`，不能把无法证明的复杂 SQL 伪造成字段直连。
- 新增轻量 OpenLineage RunEvent 接收能力，支持 `START`、`RUNNING`、`COMPLETE`、`FAIL`、`ABORT` 和 `OTHER` 状态；事件保存 `eventType`、`eventTime`、`producer`、`schemaURL`、`run`、`job`、`inputs`、`outputs` 和受控 facets，按事件幂等键去重。
- OpenLineage dataset 的 `namespace + name` 映射到内部资产；未匹配的输入/输出只保留事件，不自动创建缺少连接、数据库或 Schema 合同的业务资产。匹配成功后生成表级关系；标准 `columnLineage` facet 仅为可解析的输入/输出字段生成字段级关系。
- 事件状态只记录运行证据，不替代批次或工作流状态。事件接收失败不得阻断既有任务；事件接口和查询接口沿用 `dataPlatform:read/design` 权限，原始事件不得保存凭据、请求体、密钥种子或 SQL 中的敏感值。
- 支持按 `job.namespace`、`job.name`、`run.runId` 和时间范围查询事件，并在血缘关系上标识来源为 `native` 或 `openlineage`。AI 使用方优先读取 OpenMetadata 风格实体投影和已确认字段关系，不直接读取原始事件 JSON。
- 第一版只提供标准事件接收、幂等审计和只读投影，不提供事件反向修改资产、删除血缘、自动发布 OpenMetadata 服务或将事件转发到外部消息系统的能力；未来可在不改变内部事实表的前提下增加 Kafka/HTTP exporter、OpenMetadata API exporter 和 AI 检索索引。

验收要求：同一 OpenLineage 事件重复提交只产生一条事件记录和一组血缘边；含 `columnLineage` facet 的事件生成字段关系；不含 facet 的事件只生成表级关系；未知 dataset 不创建虚假资产；事件查询与 OpenMetadata 风格导出不泄露敏感信息；既有四层血缘 API、页面、任务运行和 SM4 回归保持通过。

### 9.3 数据库分组统计与库业务层级配置

本节中的数据库分组统计和库业务层级编辑 UI 仅保留历史兼容说明。新版本不再在当前系统页面维护该信息，库、Schema、表、字段、标签、质量和治理均以 OpenMetadata 原生模型和 UI 为准。

血缘中心的统计和筛选不能只停留在资产或表级。系统增加数据库维度的只读聚合，并提供管理员可维护的库业务层级配置。

- 数据库分组键为 `engine + connection + catalog + database`；同名数据库在不同连接或 Catalog 下必须分开统计，不能合并为一个展示组。
- 每个数据库组至少展示资产数、血缘关系数、字段级关系数、待确认关系数、SM4 传播关系数，以及当前库业务层级和最近更新时间。
- `数据层级` 继续使用现有 `restored/raw/standard/secured`，只描述单个资产在四层链路中的位置；不得用库业务层级替代或回写该字段。
- `库业务层级`是人工配置字符串，支持 `ODS`、`DWD`、`DWS`、`ADS`、业务域名称或用户系统中的其他稳定标签；保存前后必须真实回读，刷新页面不得丢失。未配置时显示“未配置”，系统不得根据库名或表名自动猜测。
- 配置实体只保存库定位信息、业务层级、备注、修改人和修改时间，不保存凭据；配置修改只影响统计、筛选和展示，不改写资产、血缘边、批次、任务、调度或 OpenLineage 事件。
- 血缘中心支持按数据库组筛选；筛选后资产图谱、关系表、摘要指标和 OpenMetadata 风格投影必须使用同一筛选范围。跨库关系在来源库和目标库的组统计中各计一次，并在关系详情中保留真实两端。
- 库业务层级配置入口放在数据血缘中心和数据自动化任务工作区的“数据库治理”区域；页面采用保存/刷新/回读闭环，不能通过删除资产或重跑任务完成配置。

验收要求：至少准备两个同名不同连接或 Catalog 的数据库，统计必须分成两个组；配置一个库的业务层级后刷新仍保持，另一个库不受影响；按库筛选时资产、关系和指标一致；现有四层数据层级、OpenLineage 事件、任务运行和 SM4 关系回归保持通过。

### 9.4 OpenMetadata 原生 UI 与当前系统任务集成（当前正式方案）

本轮实现边界：系统提供 OpenLineage 接收、脱敏、幂等审计和按需 API Bridge 同步；资产登记、血缘提交和 OpenLineage 事件落库后进入异步 outbox，由现有 data-platform Worker 派发，失败最多重试 5 次并保留失败记录，不阻塞业务任务。

本阶段将血缘中心从“自研图谱和数据库治理工作台”重构为 OpenMetadata 原生 UI 集成入口。当前系统不再复制 OpenMetadata 的搜索、资产详情、字段血缘、质量、标签、域和治理页面；当前系统继续负责任务定义、批次状态、调度、运行日志、业务恢复/同步/标准化/加密，以及向 OpenMetadata 提供可审计的资产和运行事实。

- OpenMetadata 原生 UI 是血缘、资产搜索、字段级血缘、Profiling、Data Quality、Tags、Glossary、Domain 和后续 AI 上下文的唯一正式展示入口；当前系统的“数据血缘中心”只显示连接状态、同步状态、最近同步结果和“打开 OpenMetadata”入口，不再显示自研血缘图、数据库分组指标或库业务层级编辑表单。
- 当前系统保留 `DataAsset`、`DataLineageEdge` 和 `DataLineageEvent` 作为任务执行审计与兼容事实，不删除历史记录；这些内部记录不再作为第二套用户治理 UI 的来源。数据库层级旧表和兼容 API 暂时保留读兼容，新的治理字段不得继续扩展到当前系统 UI。
- 新增 OpenMetadata 连接配置：`OPENMETADATA_URL`（原生 UI 地址）、`OPENMETADATA_API_URL`（默认由 UI 地址推导 `/api`）、`OPENMETADATA_API_TOKEN`（仅服务端使用，不回显）、`OPENMETADATA_SYNC_ENABLED` 和请求超时。未配置或未启用时，任务和本地 OpenLineage 审计照常运行，页面明确显示“未连接”，不得伪造已同步状态。
- OpenMetadata Server 不随当前系统 API/Worker 镜像内置；部署环境必须先提供可访问的 OpenMetadata UI/API 服务，再注入上述配置并重启 API/Worker。当前系统只能检测配置状态并给出部署引导，不能用本地投影冒充 OpenMetadata 原生服务。
- 资产采集优先使用 OpenMetadata 原生 Doris、Oracle、MySQL 等 Database Service Connector，负责数据库、Schema、表、列、使用统计、Profiler、质量和标签等元数据；当前系统不重新实现连接器采集逻辑，也不在页面中手工维护库业务层级。
- 当前系统任务完成资产登记或产生可证明血缘后，生成标准 OpenLineage RunEvent，并通过可配置的 OpenMetadata API Bridge 同步表实体和血缘关系。表实体使用稳定 `fullyQualifiedName`；更新使用 OpenMetadata `PUT /v1/tables`，血缘使用 `PUT /v1/lineage`，字段映射写入 `lineageDetails`。不存在对应 Database Service/Schema 合同时只记录同步失败，不自动创建虚假连接或资产。
- 同步内容必须携带当前系统的 `pipeline_id`、`batch_id`、任务运行 ID、工作流版本和节点信息作为受控 custom property 或 pipeline reference；不得传输凭据、密钥种子、明文口令或未经脱敏的 SQL 请求体。OpenMetadata 同步失败不得回滚或阻断恢复、同步、标准化和加密任务，必须进入可重试的同步结果记录。
- 任务页面只保留任务状态、批次、运行日志和 OpenMetadata 原生 UI 跳转；资产表中的“查看血缘”改为“在 OpenMetadata 中打开”，使用稳定 FQN 或资产链接，不再打开当前系统自研图谱。
- 旧自研血缘 API 和 OpenLineage 接收 API 在迁移期保持只读/兼容，新的写入优先走任务事件和 OpenMetadata Bridge；不得再为旧图谱增加新的筛选、统计、治理编辑或可视化能力。

验收要求：配置 OpenMetadata URL 后当前系统能显示连接状态并打开原生 UI；关闭同步时既有任务和本地事件审计不受影响；启用同步后，隔离资产可通过 OpenMetadata 原生搜索、表详情和上下游/字段血缘查看，且任务 ID、批次 ID 和工作流信息可追溯；同步失败不阻断业务任务并可重试；当前系统不再渲染自研图谱、数据库统计和库业务层级编辑 UI；旧任务、调度、运行日志、SM4 和 OpenLineage 幂等回归保持通过。

## 10. 兼容性边界

- 旧恢复任务、同步任务、离线流程、SM4/SM3 任务、调度和运行记录保持不变。
- 自动化流水线只引用或克隆既有快照，不回写原定义。
- 默认关闭自动监听和自动加密；升级后不会自行扫描生产目录或处理历史文件。
- 第一版只支持 Oracle Data Pump 自动入口；传统 exp、加密 DMP、Transportable Tablespaces 和无法建立恢复合同的文件进入阻断状态。
- 删除流水线不删除历史批次、资产、血缘、业务表或既有任务。

## 11. 验收

1. 隔离目录新增 Data Pump DMP 后只创建一个批次，文件未稳定时不恢复。
2. 恢复成功后记录实际目标 Schema，并自动创建一次同步运行。
3. 相同 Schema 指纹再次进入时匹配同一蓝图；不兼容结构进入确认或阻断。
4. 标准化运行绑定冻结生产版本和标准目标。
5. 能从标准字段追溯至 Doris 原始字段及 Oracle 恢复字段。
6. 直接血缘的敏感字段能生成源表 SM4 草案；复杂表达式不会自动执行。
7. 任一阶段失败后可从断点恢复，已成功恢复/同步不会重复执行。
8. 测试前后既有任务、密钥、调度和离线版本数量及内容不变。
